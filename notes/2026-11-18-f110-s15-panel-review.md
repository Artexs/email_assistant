# F110 stage 15: panel review "Check 10 decisions" (notes for stages 25 and 26)

Flag `panel_review` (default off, epic `E4-B`, remove-by 2027-03-01; registry order: after `trust_ladder`). No migration, no table, no
`TERMS_VERSION` bump (see "Privacy" below). The page is its own page `review.astro` (not a section of the report page): the nav is unchanged
(active key `settings`, as the report page), and the only entry is the optional link on the report page.

## API (any member; flag first)

- `GET /api/review/sample?mailboxId=<uuid>`: up to 10 items (`PANEL_REVIEW_SIZE`, tied to `REVIEW_PAGE_SIZE` by a test). Same sample rules as
  Telegram `/review` (`listReviewSample`: real mail of 30 days, no feedback row, no test mail, random order; seed = user id + request time,
  so each load is a new sample). Item: `emailId`, `receivedAt`, `fromName`, `subject`, `category`, `confidence`, `aiText` (the stored
  `save_summary` text; null when none). Also `delegation` (an active delegate exists).
- `POST /api/review/label`: body `{ emailId, verdict: "right" }` or `{ emailId, category }` (category from `reviewLabelCategories`).
  Writes through `recordFeedback` with source `review` and `skipIfSame`; answer `{ saved, verdict, aiCategory }`.
  409 `needs_category`: `right` on an `unsure` mail. 409 `no_delegates`: `delegation` named while the organization has no active delegate
  (a mail that already is `delegation` may be confirmed with `right`).
- Flag off: both routes 404 for every role, also with a bad id or body (the flag check is the first middleware). A mailbox or mail of another
  organization, an unknown id, a bad id or a missing `mailboxId`: the same 404 `not_found`. Every query filters `org_id`
  (`getMailbox`, `listReviewSample`, `getLabelTarget`, `recordFeedback`, `listMailExamples`, `listDelegates`).
- The label unlocks nothing: it only writes a `triage_feedback` row, which the tripwire (a `wrong` after a grant) and the real-label block
  already read. A test checks that the mailbox settings stay equal after labels.
- Code: `triage/review-panel.ts` (service), `triage/review-routes.ts`, `reviewDocs` in `triage/api-docs.ts`, schemas in
  `packages/core/src/web/review.ts` (`PanelReview*` names: `ReviewItem` is taken by the Telegram renderer).

## Privacy (mail text)

- The answer holds mail text: the sender's display name (`email_headers.from_name`, never the address), the subject and the stored AI
  summary. It comes from stored rows, never from a model call. Only a signed-in member of the organization that owns the mailbox gets it
  (the mailbox belongs to the organization; there is no per-user mailbox owner, so "any member" as in the stage text and as the trust examples).
- The review code opens no logger and prints nothing (a test reads the two source files). No audit row.
- The Telegram `/review` page already shows sender and subject, so there is no new third-party flow: the page is behind login and the text
  goes to no outside service. No change to the legal papers, so no `TERMS_VERSION` bump. (The coordinator may still decide to name the page in
  the privacy text.)

## Web

- `/review?mailbox=<id>`: mailbox selector with 2 or more mailboxes (as the report page), 10 items, each with `✅ Right` (hidden for an
  `unsure` mail), a native category select with a label and a `Save` button (keyboard: Tab reaches each control; `Save` is disabled until a
  category is chosen), and an inline answer. `Done`, or the last answer, shows the thank-you and a link back to the report. No required
  step: no onboarding item, no badge. A paused organization gets disabled buttons (`canWrite`).
- The report page shows the stage 14 text `rep_review_suggest` + link only with `panel_review` in `me.features` and a shown category list
  (`reviewHrefFor` in `lib/review-view.ts`; `PANEL_REVIEW_HREF` is gone, `ReportContent` takes `reviewHref`).
- Texts: block `F110 stage 15` at the end of the key list in `en.ts` and `pl.ts` (`title_review`, `rv_*`). Saved answers reuse `act_toast_*`,
  categories reuse `act_cat_*` / `act_tag_*`, `save`, `rep_off`.
- Docs flag registry: `apps/docs/src/flagged-text.ts` `panel_review: ["title_review", "rv_thanks"]`.

## E2E

- Own organization per project `E2E Review <project>` (`e2e-review-rows.ts`): flags `panel_review` + `trust_ladder`, one mailbox, a done
  history check, 12 real mails (non-synthetic Message-ID, `@review.example` senders), mail 1 has a stored summary. The seed file has `reviewOrgs`.
- `apps/web/e2e/tests/review.spec.ts` RV1 to RV7 (serial; each test reads the labels the one before left).

## Limits / for the Opus review

- The item shows the stored AI summary only; the "reason" of the stage text has no stored plain text (only a reason code), so none shows.
- The sample is of one mailbox (the Telegram page samples all mailboxes of the organization).
- `delegation` as a label is offered only with an active delegate; the server refuses it otherwise (the Telegram buttons have no such check).
