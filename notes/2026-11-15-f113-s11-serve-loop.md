# F113 stage 11: serve loop, what a later stage must know

Code: `apps/server/src/modules/lab/serve.ts` (loop), `serve-parts.ts` (wiring over DB, mail client, fake Telegram), `serve-files.ts` (lock, `serve.json`). Rules: `docs/capabilities/live-lab.md` rule 21.

- **Lock.** `locks/serve.lock` holds `{host, ns, pid, token}`. The host name is NOT a container id in the sim stack: `lab` joins the network namespace of `fake-telegram` (`network_mode: service:`), Docker copies the joined container's host name (moby `daemon/container_operations.go`), so every lab container and every `docker compose run lab` shares it, with its own PID namespace and pid 1. So `ns` (`readlink /proc/self/ns/pid`, random per process if unreadable) is part of the identity. Stale at once: same host AND same ns AND (pid dead, or same pid with a token not held here = container restart). Across namespaces: only the 90 s heartbeat age (the holder touches every 10 s). `touch()` returns false for a foreign token or a missing file; `runServe` then stops and exits 1 (`lock_lost`). The first fix (host + pid only) was wrong: review 11 NOTE 1.
- **Ledger line without stop.** Each tick ends at once any active run that has a ledger line (`error:ledger_line`).
- **First tick order.** A run with no `seen` event of part `tg` runs executive, bots, injector (not injector, bots, executive). If that executive tick throws, the injector skips that tick. Later ticks use the spec order.
- **finish.** `finishRun` writes the ledger line first, then `stopRun`. A crash between them leaves an active run that the next tick ends. The ledger line of an `error:unpriced` run holds the priced part only (a lower bound).
- **modePlan.** `startLabRun` never sets `LabRun.modePlan`. Stage 14 (demo reset) must write it into `run.json` for the demo run; until then the mode step is a no-op.
- **Fake restart.** The executive can lose cards after a fake restart (by design). The scorer counts the expired approvals. No retry exists.
- **Stage 14 carry-over.** After a UIDVALIDITY change a bot UID can point at another mail: compare the Message-ID with the plan key before a send, or reset the bot cursors and plans.
- **N3 (F111 review 3).** `startLabRun` now takes `models: {model, endpoint}[]`; `lab.ts` passes the endpoint kind of each role's provider (`llmRoleTable(config).providers[provider].endpoint`). Own = never refused; eu needs an eu price row.
- **Lint.** `eslint.config.js`: `imapflow`, `mailparser`, `nodemailer` only in `modules/mail/`, `modules/lab/`, `platform/auth-mail.ts`. Probe: a file in `modules/triage/` that imports them gives 3 errors; with the rule removed, 0.
