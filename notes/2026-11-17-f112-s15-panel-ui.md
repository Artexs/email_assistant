# F112 stage 15: panel Help link and "What is new" card

- Releases reach the panel through the Astro integration `apps/web/integrations/changelog-releases.ts`. It parses `CHANGELOG.md` at config time (a bad file stops the build) and serves the Vite virtual module `virtual:ea-changelog-releases` (only released versions with "For users" lines, with both languages). No env or file switch.
- `deploy/Dockerfile` copies `CHANGELOG.md` to `/app` before `bun run web:build`; the unit test in `apps/web/integrations/changelog-releases.test.ts` checks the order. Docker was not usable in the job (socket permission denied): T4 relies on the CI `image` job.
- UI: `components/shell/WhatsNew.tsx` (`HelpLink`, `WhatsNewCard`, `WhatsNewSlot`); the Help link sits in the sidebar footer and in the phone menu sheet. The card state is read once per page load in a `useState` initializer.
- `useLocale()` gives "en" on the server render, so a component that needs the locale value calls `useLocale()` (to subscribe) and then `getLocale()` (what `t()` reads).
- `whatsNew`, `compareSemver`, `parseChangelog` and `docsUrl` now come from `@ea/core/web` (the browser entry), not `@ea/core`.
- e2e `docs-links.spec.ts` sets the flag with `org-flag.ts` and writes the locale through `PATCH /api/me/locale` with an `origin` header (without it the write fails). The e2e DB of the job is `f112_s15_e2e` (keys in the job's `.env`).
- Guard-removal log: `/tmp/f112-s15/guard-removal.log`.
