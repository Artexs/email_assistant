## What the page does

- `/report?mailbox=<id>`. No `?mailbox=` or an unlisted id: the newest connected mailbox. A selector shows with 2 or more mailboxes (it names
  the user's own mailboxes, as Settings does). The page asks for nothing when `trust_ladder` is not in `me.features` (it shows `rep_off`).
- One state per `GET /api/trust/:mailboxId`: no check (`rep_starting`), open check (`rep_progress`, polls every 30 s; an end state does not
  poll), `no_result` (one sentence per `noResultReason`, then the categories), `done` (summary and the categories).
- Per moving category: counts (`history.total` checked, `history.wouldMove` would move), the proof line, the history line and the pause line
  (`trustLines` of stage 13), and one status phrase (on / recommended / not recommended yet). Nothing else.
- Owner only: `Turn on recommended (<categories>)` (shows when at least one category is `evidence.recommended` and not `auto`), calls
  `POST /api/trust/:id/recommended`, shows the categories and the new mode, replaces the view with the answer's `view`. `Check again` (end states)
  calls `POST /api/trust/:id/history-check`; `check_running` (409) is a toast. Members see the text `rep_owner_only` and no button.
- The active nav key is `settings` (no new tab: the phone tab bar keeps its limit). The entry points are the card link of stage 13 and the
  onboarding step.

## Decisions taken (defaults)

- **No example mails on the page.** The stage text asked for up to 3 example mails (sender name, subject, date) for a `fail`. The job
  instruction says the page shows counts and fixed phrases only, never mail text, subjects or addresses. The page follows the instruction:
  `ReportContent` and `report-view.ts` never read `view.examples`. A unit test puts a sender name, a subject and an address into the examples
  and checks that no state, role or language prints them. The examples stay in the API view for the panel review (stage 15) to use.
  Question for the owner: do they want the examples back on the report? (If yes: a decision to show mail text on the page.)
- **Onboarding (flag on):** steps mailbox, channel, report, rules; the mode step is gone. `channel` = Telegram linked, or the member's
  `report_channel` is `mail` or `both`. A server without a bot never blocks on the channel (as before). `report` = any mailbox of the
  organization has a `done` or `no_result` check (`hasEndedCheck`; an open check does not count). `done` = mailbox, channel, report. Flag off:
  the old rule (mailbox, Telegram or no bot, mode chosen). With the flag on, the mode stays `shadow` until the user taps the button.
- `homePathOf` uses the same function, so an organization with the flag on and no ended check lands on `/onboarding`.
- The link to the panel review (stage 15) is off: `PANEL_REVIEW_HREF` in `lib/report-view.ts` is `null`. The stage 15 worker sets the path
  (the texts `rep_review_suggest` and `rep_review_link` exist in en and pl).

## E2E

- The trust organization of the project got three more mailboxes, created after the card mailbox (the Settings page shows the first one, so the
  card spec is unchanged): `done` (shadow mode; `notification` recommended, `spam` failed, `info` paused), `running` (a `classifying` check with
  `next_attempt_at` one year ahead, so the history job of the e2e server never claims it), `noResult` (`no_history`, no trip: all three moving
  categories recommended). Rows: `e2e-trust-rows.ts` `seedReportRows`. Spec: `apps/web/e2e/tests/report.spec.ts` (R1 to R8).
- No test taps `Check again`: the e2e server runs the history job, which would claim the queued check against the GreenMail with a fake login.
  The route has its own test (stage 11); the button states are covered by `report-view.test.tsx`.

## Limits

- The summary line `Mails checked: n` counts stored items (`check.checked`); the per-category line uses the stored result (`history.total`). The e2e seed
  stores no items, so its summary reads 0 next to 200 in the categories. Real checks agree.
- Polish texts are for the Opus review (list in the final message of the job).
