# F102 stage 09: card sync notes

- Consent decision (carry-over from the stage 05 review): no `TELEGRAM_CONSENT_VERSION` bump. The panel link holds our own panel address (`WEB_BASE_URL`, operator config) and a send id: no mail-derived data. It is off while the flag `approvals_page` is off or `WEB_BASE_URL` is unset. The edit rows hold the card text that the user already got, plus fixed phrases of our own code. Rule of the owner decision of 2026-11-15 (F109): bump for a new kind of mail-derived data only.
- Hook input `at` (stage 08 review N3): `DelegationHooks.onSuperseded` takes `at`; `delegations.updated_at` uses the clock of the caller.
- `onDecided` is not called for the timeout expiry inside `approve` (the tap edits its own card) nor by the hourly job (Q18: no card edit). The type keeps `expired` for a later caller.
- A card edit is `failed` / `no_target` when the user linked another chat after the card went out (`chat_links.linked_at` later than the card `sent_at`): message ids belong to one chat, an edit would hit another message.
- Natural DB errors inside the hook cannot be provoked by a test (the app role cannot create triggers; `outbox` checks cover the data). The test uses a send scope that throws inside the hook; the savepoint protects against database errors the same way.
- Order of edit rows inside one transaction: rows that share `created_at` have no stable order; tests sort by message id.
