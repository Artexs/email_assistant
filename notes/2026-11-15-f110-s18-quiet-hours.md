# F110 stage 18: quiet hours per member and the report channel (seam map)

For the workers of stages 19 and 20 and for the stage 25 docs.

## Where the code is

- Hours: `memberships.quiet_start` / `quiet_end` (both null = default `22:00`–`07:00`; equal = none). `quietHoursOf(start, end)` in `packages/core/src/digest/local-time.ts` turns the two columns into a `QuietHours`. `isQuietTime`, `quietEnd` and `lateMin` take it as an optional last argument.
- Sender: `channels/sender.ts` `quietOf(row)`. It reads the flag `user_quiet_hours` once per organization of the batch (`isFeatureOn`) and the hours of the users of the batch with one query (`listQuietHoursOf` in `tenancy/repo/memberships.ts`). Digest and `approval_edit` skip the check. The mail channel rows of stage 19 and 20 pass through the same loop: a mail row of kind `digest` is never held, as before.
- SLO: `channels/metrics-repo.ts` `UrgentCandidate.quiet: QuietHours[]` (sent notice: the hours of its user; no sent row: the hours of each pending or sending urgent row; empty: default). `operator/slo-checks.ts` applies the flag per organization and takes the smallest wait. M5 (`metrics/m5.ts`) keeps the default hours on purpose (Q18).
- `/status`: `channels/commands.ts`, new text `noQuietHours`; the Polish line now reads `Godziny ciszy` (the old `Cisza nocna` was wrong for day hours).
- Route: `GET/PATCH /api/me/notify` in `channels/routes.ts`, logic in `channels/notify-settings.ts` (`changeNotify`, `notifyViewOf`), schema `packages/core/src/web/notify.ts`, docs `channels/api-docs.ts`. The quiet group needs the flag `user_quiet_hours`, the channel group `report_mail`; a write with its flag off is 404. A body holds one group only. The audit event is `member.notify_changed` (data: `via`, `keys` = key names, never a value).
- Card: `apps/web/src/components/settings/NotifyCards.tsx` (`QuietHoursCard`, `ReportChannelCard`), mounted by `NotifySection` in `islands/SettingsPage.tsx`. No request is made while both flags are off.

## For stage 19 and 20 (report channel)

- `memberships.report_channel` (`telegram` | `mail` | `both`) and `report_mailbox_id` are stored only. A mailbox that is not `active` is refused at write time (409 `no_mailbox`); the mailbox can still turn `paused` later, so the mail sender must check the mailbox status again.
- Setting the channel back to `telegram` clears `report_mailbox_id`.
- The flag `report_mail` is registered in `features.ts` (default off); stage 20 reads it for the APPEND path.
