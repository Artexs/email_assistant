## Owner gates (default for each: prepare, do not publish)

- **G1 publish the new pages.** Read the built site: `bun run docs:build && bun run --filter @ea/docs preview`, and the cold-read answers of the coordinator scout (`apps/docs/cold-read.md`). Then the coordinator empties `OWNER_REVIEW_PENDING` in one commit; the next release tag deploys. Until then no tag deploys the docs; a manual run needs the dispatch input `publish_held_pages`.
- **G2 commit the demo seed.** Only if the C1 export is under 5 MB and scanned: `cp ~/.local/share/email-assistant/demo/demo-seed-day5.json apps/web/e2e/demo/demo-seed.json && git add apps/web/e2e/demo/demo-seed.json`. A commit to the public repo cannot be taken back.
- **G3 upload the demo video.** Only a video that `demo:record` made from the demo seed is a candidate (the e2e-seed video never is). `demo:record` on a demo seed stops with `demo_source_recording_not_built` until follow-up F151 builds it, so no candidate exists today. When one exists: `flock /tmp/email-assistant-shared-tests.lock bun run demo:record --seed <demo seed file>` writes `tmp/demo/demo.mp4`, `tmp/demo/demo.en.vtt`, `tmp/demo/demo.pl.vtt` and prints the sha256 of each. The owner watches `tmp/demo/demo.mp4`, then runs `gh release create demo-video tmp/demo/demo.mp4 tmp/demo/demo.en.vtt tmp/demo/demo.pl.vtt` (or `gh release upload demo-video … --clobber` for a new take). The release holds exactly these three files. The coordinator commits the three sha256 values to `DEMO_VIDEO_SHA256` and `DEMO_CAPTION_SHA256` (`en`, `pl`) in `apps/docs/src/demo-video.ts`. Without the pins the deploy downloads nothing. The steps are in `deploy/README.md` § Docs site.
- Recommended order: G2 and G3 before G1.
