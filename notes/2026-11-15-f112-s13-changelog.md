# F112 stage 13: changelog parser, page, deploy gate (notes for stages 07, 14, 15, 16)

- `packages/core/src/changelog.ts` (exported from `@ea/core`, no Node module): `parseChangelog`, `compareSemver`, `ChangelogError` (`message` = `<code> (line N)`, field `line`), `UNRELEASED`. Strict SemVer in headings and tags: no leading zero, no pre-release or build part (`prepareRelease` of F114 accepts `01.2.3`; the parser then fails with `changelog_heading`: the stricter rule wins). Date must be a real calendar date. `Unreleased` is valid only as the first heading; a second one is `changelog_duplicate`.
- "For users" item: `- en: <text>` then the very next line `  pl: <text>` (two spaces). Any other line in the group, a blank line between the two lines, an empty text, or an `en` line at the end of the group is `changelog_for_users_item` at the `en` line (or at the bad line). HTML comments (also several lines) and `[x]: url` link lines are skipped everywhere.
- `CHANGELOG.md` comment: example is indented 4 spaces and holds no `## [Unreleased]` line (`prepareRelease` finds the heading with `line.trim()`). `release-prepare-changelog.test.ts` (T8b, T8c) runs `prepareRelease` on a fixture and on the real file and parses the result. `Unreleased` now holds one "For users" item (docs site). Before the next release, check that the item is true (the guides are stages 07 to 09).
- Page: `apps/docs/src/changelog-page.ts` `changelogPage(markdown)` builds the page from `parseChangelog` only: `# Changelog`, `## <x.y.z> - <date>`, `- <en text>`. `IN_PLACE_PAGES` entry `{ id: "changelog", path: "CHANGELOG.md", transform, ownLink: true }`. `ownLink` = a sidebar link of its own, outside the group "Operate" (`inOperate()` in `in-place.ts`; used by `astro.config.mjs` and `in-place-check.ts`). `readInPlaceSource` applies `transform` before `splitSource`; the loader then runs `rewriteLinks` on the result. `/pl/changelog/` is the English fallback (P6).
- The raw `CHANGELOG.md` is in `inPlaceSourcePaths()`, so the content-script scan reads it (operator text too); `public-content` scans only the built output, where operator text does not appear.
- `apps/docs/src/site-map.test.ts` is created here, because stage 07 had not landed: expected ids `changelog`, `index`, `operate/install-and-run`, `operate/release-checklist`, `pl/index`. Stage 07 creates the same path: on the merge take the union of both id lists.
- `flagged-text.test.ts` (stage 07) was not there. T10's "no `FLAGGED_TEXT` string in the changelog page" is proven here only for `Offline quality lab` and by `changelogPage` publishing no operator group. When stage 07 lands, its test should also scan `changelogPage(<real CHANGELOG.md>)`. Rule for an author: a "For users" item never names behaviour behind a default-off flag (plan P2).
- Gate: `deployDecision(ref, tags, releases)`; `releases` = versions of released entries. A pushed plain `v<x.y.z>` tag with no `## [x.y.z]` entry gives `error: changelog_missing x.y.z` (exit 1, no `deploy=` output). The check runs before the newest-tag skip. A manual run and a branch push never need an entry. `main(env, readTags, readChangelog)`; the script reads `<root>/CHANGELOG.md` (`EA_DOCS_REPO_ROOT` or the repository). A changelog that does not parse fails the gate with the `ChangelogError` text. `newestRelease` now uses `compareSemver`. The workflow file changed only by one comment line.

A reader may have meant 1 to 7: the owner can reword).
