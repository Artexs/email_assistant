# F112 stage 11: `<Shot>` and the shot run (notes for stage 12 and later)

- `apps/docs/src/shots.ts`: `SHOTS` (20 = 5 pages × en/pl × desktop/phone), `shotView`, the checks of the run (`shotFeaturesProblem`, `shotTextProblem`, `shotFilesProblem`), `SHOT_TEXT_ALLOW`. `components/Shot.astro` is thin; the integration `ea-shots` (`integrations/shots.ts`, last in `astro.config.mjs`) sets `EA_DOCS_SHOTS_DIR` (default `apps/docs/public/shots`) and logs `shots: on|off` once.
- A page that uses `<Shot page="x" />` is also built as the Polish fallback `/pl/...` (Starlight). So with `DOCS_SHOTS=on` the page needs the shots of both languages: all 20 files must exist, as after `docs:shots`. Stage 12 pages: put `<Shot>` only where all 20 exist (the deploy makes them first).
- `shot_missing` names the first missing file, desktop first. Unknown page: `shot_unknown_page <page>` in both modes.
- The shot run: `bun run docs:shots` = `apps/web/e2e/docs-shots.config.ts` (own `testDir ./docs-shots`; `test:e2e` lists none of it, checked with `playwright test --list`). The panel config and the shot config share `apps/web/e2e/servers.ts` (`e2eWebServers`, `e2eLaunchOptions`) and `global-setup.ts` (the shot setup first empties `apps/docs/public/shots/*.png`). Env as `test:e2e`: `E2E_DATABASE_URL`, `E2E_MIGRATOR_DATABASE_URL` (own DB `bun run db:worktree <name>_e2e`), `CHROMIUM_PATH`; needs `bun run web:build`; ports 8081 and 8092 (flock).
- The run signs in once as the seed owner (`readSeed().owner`), asserts `/api/me` `features` is `[]` before the first shot (and again before each shot), then one test per shot in a new context (desktop 1280×800, phone `devices["Pixel 7"]`, not full page; language by the `ea.locale` storage key).
- Real finding of the public-content check in the run: the Settings page lists the client address as "this device". The panel e2e address block 198.18.0.0/15 is no documentation net (rule R3 stops the run). The run sends `x-forwarded-for: 198.51.100.200` (RFC 5737). Second finding: the Rules page help text holds `anna@firma.pl` (a fixed panel text); it is the only entry of `SHOT_TEXT_ALLOW`, and a test checks that it still stands in the panel text.
- The seed's main organization has no mailbox: Mailboxes, Settings and Activity show empty states (stage text: fine). The alt texts say so ("no mail yet, before a mailbox is connected"). F121 moves the shots to the E2b fixture.
- Stage 12 deploy: the `build` job needs the e2e DB and server env as the `e2e` job of `ci.yml` (see `ci.yml` lines of the `e2e` job). A random `CREDENTIALS_KEY` is enough. `bun run docs:shots` writes into `apps/docs/public/shots/`, `DOCS_SHOTS=on bun run docs:build` then copies the PNGs to `dist` (PNG files are not scanned by the public-content check, which reads text suffixes only: the page-text check of the run is the guard for what a screenshot shows).
- `scripts/shots-build.test.ts` runs 4 real docs builds (≈15 s) with a fixture page `zz-shot-fixture.mdx` in a temp folder outside the repository (`EA_DOCS_EXTRA_PAGES_DIR`, read by `src/extra-pages.ts`; it is no longer in `src/content/docs`, so tests that scan the pages never see it) and `NODE_ENV=production` (under `bun test` NODE_ENV=test changes Starlight's bundle and the public-content allow list then fails). Output goes to `apps/docs/.dist-shots-test/` (a dot folder, ignored by git and skipped by the glob scans; Astro cannot rename across devices into /tmp).
- Guard-removal runs: `/tmp/f112-s11/mutate.py`, summary `/tmp/f112-s11/mutation-summary.log` (52 guards, all killed; run 1 had 6 survivors, saved as `mutation-summary-run1.log`, fixed by tests and one simpler `shotView`); run-level proof `/tmp/f112-s11/mut-e2e-client-address.log`.
