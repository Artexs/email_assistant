## Decisions

1. **Two note texts, not one.** The stage said to change `appr_send_note` and `appr_edit_hint` in place to the new card wording. That wording ("edit and send in your mail client") is true only where the system stops a changed copy: a reply, or any kind while the flag `draft_copy_check` is on. The card uses the same rule (`view.kind === "reply" || view.copyCheck === true`). For a delegation with the flag off the old text stays; a changed text there would invite a double send. New keys `rp_send_note_editable`, `rp_edit_hint_editable`. Undo: change `copyChecked` in `lib/replies-view.ts` to return true.
2. **`endReason` in the detail.** The detail of an `expired` send names the close reason (`status_reason` of the eight `closeSendReasons`). The list holds waiting and held sends only, so the reason shows in the detail. A timeout has none.
3. **`replyAllAdds`.** The panel must show the added addresses before the tap; the view had only the boolean `canReplyAll`. The addresses are on the read model (not on the card view: an older release rejects new strict view keys, see the stage 13 review).
4. **Activity key `reply`.** `{ sendId: string | null }`, absent while the flag is off. The button is for an owner who may write; the server checks everything again. Cost: one flag read, and with the flag on one query for the whole page (the budget test of `reports-activity.test.ts` is 10 now, was 9).
5. **Reply all and Use Reply-To are toggles.** A second tap goes back to `from` (the recipients route accepts `from`).
6. **`instruction` of the read model is not shown.** The panel has the field for the next line only; it never prints a stored line.
7. **Redraft e2e uses browser answers.** The model is off in the e2e server. `page.route` answers `POST /api/approvals/:id/redraft`, `POST /api/replies` (clean mail) and `GET /api/replies/requests/:id`; the real routes run in the integration tests with a fake model. Blocked, Reply all, Use Reply-To, Edit and Approve run for real.
8. **Step 3 (consent in the panel)** is the card of F116 (`TelegramLink`, `loops-panel.spec.ts` T8). Nothing new here; the consent text and version stay in stage 17. **No `TERMS_VERSION` bump**; `reply_drafts` stays off by default.

## Limits (for stage 17 to write down)

- A page reload while a redraft waits loses the wait state: the Redraft button turns on again, and a second line gets the same `requestId` from the server (only the first line is stored). Server-side fix would be a 409 for a waiting redraft of the same send.
- The panel shows the draft quote closed; the cut quote text of an old view without `quote` on the detail is shown as before.
- Reply all is limited to 10 others by the service; the button shows only for 1 to 10 others.
