## Conflicts between a capability page, the code and the plan (the code won)

- `docs/capabilities/digest-and-notices.md` rule 9 ("while `POLISH_MESSAGES_ON` is false, every member gets English"): the constant does not exist (`grep -rn POLISH_MESSAGES apps packages` finds nothing; only the capability page holds it). `chat_links` reads `users.locale` and a null value gives `pl` (`apps/server/src/modules/channels/repo.ts`, function `toLinkedChat`). The page `language` says: Telegram uses the saved language, else Polish; the panel uses the saved language, else the browser language. The capability page is not edited here: fix its sentence in a docs pass.
- Stage 08 text: "what the system does with `✅ n`, `✏️ n`". The capability pages say only that they write a feedback row. The page says that the system saves the answer, does not move or sort the mail again (`recordFeedback`: "It never queues the mail for a new triage"), and that the answers feed the check of the category.
- The digest and Activity give `✅` only for Urgent, Reply, Info, Notification and Spam (`isLabelCategory`). A Delegate mail has only `✏️`, like an Unsure mail. The capability page names only Unsure. The page says both.
- `create_draft` is off by default (`toolSwitchesSchema`), and "Turn on the usual switches" leaves it as it is. So `approve-a-send` and `delegate-and-follow-up` name the switch "Write delegation drafts" in "Before you start". The tutorial says only "assist mode"; it is true but incomplete for drafts. Not changed in this stage.
- The reminder count `reminders_sent` counts reminders that went out, not planned ones. A skipped set can come again after 3 days (`bumpReminder` runs in `onReminderSent`; the gap runs from `last_reminder_at`). The page says so.
