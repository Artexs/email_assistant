## What stage 10 and later call

- `withMailboxOAuthLock(pool, mailboxId, fn(tx))`: one transaction on the pool under `pg_advisory_xact_lock(hashtextextended('mailbox_oauth:<id>', 0))`. Reconnect and the refresh of stage 10 must both use it. `readOAuthSecret(tx, secrets, ctx, id)` and `saveOAuthSecret(tx, secrets, ctx, id, secret)` read and replace the secret (AAD `mailbox:<id>`, kind `oauth`). `OAuthSecret = { v: 1, provider, refreshToken, tenantId, scopes }`; `encodeOAuthSecret` / `decodeOAuthSecret` throw `HardError` with a fixed message.
- `applyOAuthGrant(deps, ctx, grant, actor)` → `{ ok: true, code: "connected" | "reconnected", mailboxId }` or `{ ok: false, code }`. `ApplyGrantDeps` = `db` (pool), `secrets`, `clients`, `openProvider`, `verifySmtp`, `oauthTokens?: { drop }`, `now`, `timeouts?`.
- `MailOAuthClient` now has `spec` (the provider registry entry it was built with). Connect reads hosts and `sendVia` from `client.spec`; Reconnect logs in at the hosts stored on the mailbox row.
- **Stage 10 must wire the real token cache**: `WebExtras.mailOAuthLogin.oauthTokens` is absent in `apiPublicRouters` (web.ts), so a Reconnect drops nothing today. Pass the cache `drop` there.
- `finishMailboxReconnect(db, ctx, id, { status, at })` (repo): sets status and `auth_reason = NULL` in one UPDATE (the table CHECK allows a reason only in `auth_error`). Stage 10 sets `auth_error` and `auth_reason` in one UPDATE too, and clears the reason on every way back to `active`.
- New audit event `mailbox.reconnected` (data: `mailbox_id`, `via`, `provider`, `reactivated`). `mailbox.connected` for OAuth adds `method: "oauth"` and `provider`.
- `insertMailbox` takes `sendVia` and `oauthProvider`; `insertCredentials` / `updateCredentials` take `secretKind: "oauth"` (`CredentialKind`).

## The callback route

- `GET /api/mailboxes/oauth/:provider/callback` is mounted through the new `WebDeps.publicRouters` (platform/http.ts), before the session guard, built by `apiPublicRouters` in web.ts. Only GET is public: a POST to the path gets the 401 of the guard.
- It reads the session itself (`readSession`), takes the tenant from the oldest membership of the session user (as `requireTenant`), checks the owner role, then `withTenantScope`, the suspended check, `finishOAuthCallback` (user and organization of the session), `applyOAuthGrant`. Every other outcome is a 303; a throw anywhere becomes `oauth_failed` and one log line with the error name only.
- Order choice: the owner and suspended checks run BEFORE the state is consumed. A demoted owner or a suspended organization leaves the state row in place (it expires after 10 minutes; retention deletes it). A worker may move the checks after the consume if the owner wants single use in that case.
- `Location`: `/mailboxes?oauth=<code>`, `&mailbox=<id>` on success, `&provider=<provider>` for `admin_consent_required`. No session: `/login`. Stage 16 must read these query values.
- `HIDDEN_ROUTES` holds the route (it answers 303, `apiDoc` needs a 2xx JSON schema).

## Behaviour that a later stage may trip on

- Connect: flag check (`mail_oauth_<provider>`), duplicate check, limit check, IMAP login with `user = grant.address`, then Google an SMTP XOAUTH2 login, or Microsoft one `refresh(refreshToken, "graph")`. `MailAuthError` → `protocol_disabled`; another login fault → `oauth_failed`; any `OAuthGrantError` of the graph refresh → `admin_consent_required`; a soft error → `oauth_failed`. A rotated refresh token of the graph refresh is stored.
- The Sent switch: every OAuth mailbox gets a `mailbox_sent_sync` row with `enabled = isFeatureOn(sent_sync)`, as `connectMailbox` does. No flag was turned on for a real organization.
- Reconnect works with the provider flag off, keeps the mailbox id and all rows, replaces the secret under the lock, `auth_error` / `host_blocked` → `active`, `paused` stays. A mailbox whose `oauth_provider` differs from the grant, or whose credentials row is not `oauth`, gives `oauth_failed`.
- The fake token server has `failNextRefresh(answer)` (fails the next refresh-token request; a code redeem before it passes).
- GreenMail has auth off: the happy path proves the XOAUTH2 exchange, not a token check. Refusals use a stub `openProvider` / `verifySmtp` that throws `MailAuthError`.
