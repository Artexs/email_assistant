# F110 stage 03: trust tables, copies of values, and what later stages must keep

Migration `db/migrations/20261115180001_trust_ladder.sql`. Repository `apps/server/src/modules/trust/repo.ts`. Written by the stage 03 worker.

## Every place a value is copied (read before any delete or erase rule)

| Value | Source | Copy | What removes the copy |
| --- | --- | --- | --- |
| category, confidence, reason code of a mail's decision | `triage_results` | `history_check_items.{category, confidence, reason_code}` (source `triage_result`, stage 07) | the item goes with its mail (`email_id` FK cascade): DSR erase (`delete from emails`), mailbox delete, org delete. No text: retention has nothing to clear |
| acted-on flag of a mail | `email_flags` (`answered`, `flagged`) and `triage_feedback` | `history_check_items.acted_on` (boolean) | same cascade |
| counts per moving category (acted, moved, total, wouldMove, upper) | sums over the items | `history_checks.result` (jsonb) | goes with the check: mailbox or org delete. A DSR erase of one mail leaves the sums (counts only, no id, no address). Decision: keep |
| evidence key (provider, model, prompt version, endpoint host of an own endpoint) | running config at the check start | `history_checks.key` (jsonb) | goes with the check. Not personal data |
| cost in USD | `llm.call` rows | `history_checks.cost_usd`, `history_check_items.cost_usd` | same as above |
| counts of corrections that caused a trip | `triage_feedback` rows | `autonomy_trips.counts` (jsonb) | goes with the mailbox or org |
| report mailbox id | `mailboxes.id` | `memberships.report_mailbox_id` | mailbox delete sets it to null (`SET NULL (report_mailbox_id)`); the membership stays |
| trust notice counts (stage 10) | the two tables above | `outbox.view` / `outbox.text` of kinds `trust_report_ready`, `autonomy_paused` | the existing outbox retention and DSR rules; stage 10 registers the kind in `NOTICE_MAIL_CONTENT` as `no_mail` |

No new table holds mail text, a subject or an address. Registration (`privacy/export-map.ts`, `privacy/address-map.ts` as `NOT_PERSONAL`, `DELETE_SEEDS` and `fillMailbox`) is in the same commit chain.

## Facts a later stage needs

- The contract mark `-- contract: v0.1.0` covers the whole file (`db:check-migrations` reads one mark per file). Review check by hand: `outbox_kind_check` and `outbox_channel_check` only widen (test `outbox: ... the kind list only widens` in `trust-schema.test.ts` compares the lists with `20261115150001_outbox_sent_missing.sql`).
- The `result` column of `history_checks` has the shape `historyResultSchema` (`trust/repo.ts`): one entry per moving category with `outcome, acted, moved, upper, total, wouldMove`. Stage 07 must write this shape.
- `queueHistoryCheck` returns the new id, or null when an open check exists. `insertTrip` returns the id or null. `historyResultFor` returns a record with all three moving categories (null for a category without a result).
- `autonomy_trips.category` allows the five bar categories; `history_check_items.category` allows all seven triage categories.
- `history_checks_no_result_pair_check`: `status = 'no_result'` if and only if `no_result_reason` is set. A job that ends a check as `no_result` must set both in one update.
- `ON CONFLICT` target of `queueHistoryCheck` is the partial index (`mailbox_id` where status not in `done`, `no_result`). If a stage changes the open statuses, change index and repo together.
- Race tests use `pg_blocking_pids` to wait for the second writer; `pg_stat_activity` hides wait events of another role.
- The owner (`migrator`) cannot `SET ROLE app`: RLS tests run on the app connection only.
- `trust` sits in layer 5 of `layers.json` (`docs/diagrams/module-graph.*` regenerated, no new edge yet).
- Other migration jobs: F115 stage 03 also adds a migration. Never run next to it; merge order decides the timestamps.
