# F115 stage 01 — drafter core: seam map, choices, limits

Stage file: `spec/features/active/F115-e6a-reply-drafts/stages/stage-01-drafter-core.md`. No real LLM call ran in this stage.

## Where the code is

- Core, `packages/core/src/replies/`: `checks.ts` (`checkReplyBody`, `REPLY_CHECK_CODES`), `entities.ts` (address, link, phone, account scanners), `views.ts` (the text views), `gaps.ts`, `language.ts`, `schema.ts` (`drafterOutputSchema`), `input.ts` (`DrafterInput`, `cutChars`, limits), `text.ts` (`normalizeDraftText`).
- Prompt: `apps/server/src/modules/triage/prompts/drafter-v1.ts`; registered as `prompts.drafter`; `rolesWithoutPrompt` is now empty.
- Call: `apps/server/src/modules/replies/drafter.ts` (`draftReply`, `DrafterResult`, `DrafterCallError`). Module `replies` is in `layers.json` layer 3 with the edges `replies → actions` (not used yet) and `replies → triage`.

## How the scan works (probe forms)

Every scanner reads two views of the text (`views.ts`): the plain view (NFKC, no format characters, lookalike dots, slashes, dashes and digits made plain) and the decoded view (percent codes, HTML entities, `\uXXXX`, `(at)` / `[dot]` / `hxxp` words, three rounds). Header names and schemes also run through a small confusable-letter map (Cyrillic and Greek lookalikes). The tests list each form: quoted, angle brackets, `mailto:`, fullwidth, zero-width, percent, entity, bracket words, Polish words, lookalike scheme letter, slash lookalike, other-script digits, dashed and dotted phones, CR / CRLF / zero-width blank lines, bidi, tags, NEL, header lines with quote prefix, space before colon, fullwidth, lookalike letter.

Allowed text (instruction, signature, writing style) is scanned with the same code. An entity in the body passes when the same entity (same code, same compare key) is in the allowed text. The mail body is never allowed text.

## Choices that the stage text did not fix (tell the owner if one is wrong)

1. IBAN shape needs two letters, two check digits, then 11–30 letters or digits, with at least 10 digits in all. The stage text says "13–32 letters or digits" with no check digits; that shape would flag the English text "Thank you very much". A run of 13 or more digits (a card, a Polish account number) is `account_number`; 9–12 digits is `phone`. Account and card matches are cut out before the phone count, so one number gets one code.
2. Header names match case-insensitive, with a quote or pipe prefix, and `Name :` or `Name:` at the end of a line.
3. Language: the two word lists have 30 words each and share none (words that both languages use, such as "to", "a", "i", "do", were replaced). `unknown` (no hit, or a tie) passes only under 80 characters. Gap labels are cut out before this check and before the length rule of 80.
4. A CR or CRLF is a line break, not a control character. Every other C0, C1, format (bidi, zero width, soft hyphen, tags), U+2028/2029, private-use and lone-surrogate character is `control_chars`. A ZWJ emoji sequence therefore fails; a draft needs no emoji.
5. Gap syntax: `gapsOf` and `hasGaps` read NFKC text, so a fullwidth `［［x］］` counts as a gap. A label of white space only is `gap_syntax`. The model's own `gaps` field is ignored; `DrafterResult.gaps` is `gapsOf(body)`.
6. `DrafterInput.today` is a `Date` (the instant of the call). `DrafterInput` lives in core (`input.ts`) because the prompt file in `triage` cannot import from `replies`.
7. `usages`: one entry per attempt. The LLM client throws on an unreadable answer and gives no token count, so such an attempt gets an entry with zero tokens. Stage 07 writes an `llm.call` row for each entry.
8. A provider error (timeout, quota, bad key, blocked) throws `DrafterCallError { cause, usages }`; `usages` holds the finished attempts. It is not a `DrafterResult` (the stage type has only `checks` and `output`). Stage 07 maps `cause` with `llmErrorCode`. A non-LLM error goes up unchanged.
9. The retry runs once, after an unreadable answer or a failed check. A `no_draft` answer never retries. After a failed check and then an unreadable answer, the result is `failed` / `output`.

## Known limits (the code checks cannot see these)

- A number written in words, or digits split by letters, passes.
- An amount-shaped phone ("600 100 200,50") passes: the stage rule cuts amounts out first.
- `jan @ firma . pl` (spaces around the at sign) is not an address in the code; "jan at firma dot pl" is.
- Bare-domain detection uses a list of common top-level domains; `foo.zzz` with no scheme or `www.` passes.
- A confusable letter outside the small map can still hide a header name or a scheme.

## Race tests

Stage 01 has no DB, no job and no shared state. "One retry" is an in-process rule: `drafter.test.ts` runs two `draftReply` calls at once on one client and checks at most two LLM calls each and a different nonce for each request. The two-connection race tests for "exactly one / once" rules belong to stages 03 and 07 (the unique key of `reply_requests`, the one pair per request).
