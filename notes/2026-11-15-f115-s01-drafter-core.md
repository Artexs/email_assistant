# F115 stage 01 — drafter core: seam map, choices, limits

Stage file: `spec/features/active/F115-e6a-reply-drafts/stages/stage-01-drafter-core.md`. No real LLM call ran in this stage.

## Where the code is

- Core, `packages/core/src/replies/`: `checks.ts` (`checkReplyBody`, `REPLY_CHECK_CODES`), `entities.ts` (address, link, phone, account scanners), `views.ts` (the text views), `gaps.ts`, `language.ts`, `schema.ts` (`drafterOutputSchema`), `input.ts` (`DrafterInput`, `cutChars`, limits), `text.ts` (`normalizeDraftText`).
- Prompt: `apps/server/src/modules/triage/prompts/drafter-v1.ts`; registered as `prompts.drafter`; `rolesWithoutPrompt` is now empty.
- Call: `apps/server/src/modules/replies/drafter.ts` (`draftReply`, `DrafterResult`, `DrafterCallError`). Module `replies` is in `layers.json` layer 3 with the edges `replies → actions` (not used yet) and `replies → triage`.

## How the scan works (probe forms)

Every scanner reads two views of the text (`views.ts`): the plain view (NFKC, no format characters, lookalike dots, slashes, dashes and digits made plain) and the decoded view (percent codes, HTML entities, `\uXXXX`, `(at)` / `[dot]` / `hxxp` words, three rounds). Header names and schemes also run through a small confusable-letter map (Cyrillic and Greek lookalikes). The tests list each form: quoted, angle brackets, `mailto:`, fullwidth, zero-width, percent, entity, bracket words, Polish words, lookalike scheme letter, slash lookalike, other-script digits, dashed and dotted phones, CR / CRLF / zero-width blank lines, bidi, tags, NEL, header lines with quote prefix, space before colon, fullwidth, lookalike letter.

Allowed text (instruction, signature, writing style) is scanned with the same code. An entity in the body passes when the same entity (same code, same compare key) is in the allowed text. The mail body is never allowed text.

## Choices that the stage text did not fix (tell the owner if one is wrong)

1. IBAN shape needs two letters, two check digits, then 11–30 letters or digits, with at least 10 digits in all. The stage text says "13–32 letters or digits" with no check digits; that shape would flag the English text "Thank you very much". A run of 13 or more digits (a card, a Polish account number) is `account_number`; 9–12 digits is `phone`. Account and card matches are cut out before the phone count, so one number gets one code.
2. Header names match case-insensitive, with a quote or pipe prefix, and `Name :` or `Name:` at the end of a line.
3. Language: the two word lists have 30 words each and share none (words that both languages use, such as "to", "a", "i", "do", were replaced). `unknown` (no hit, or a tie) passes only under 80 characters. Gap labels are cut out before this check and before the length rule of 80.
4. A CR or CRLF is a line break, not a control character. Every other C0, C1, format (bidi, zero width, soft hyphen, tags), U+2028/2029, private-use and lone-surrogate character is `control_chars`. A ZWJ emoji sequence therefore fails; a draft needs no emoji.
5. Gap syntax: `gapsOf` and `hasGaps` read NFKC text, so a fullwidth `［［x］］` counts as a gap. A label of white space only is `gap_syntax`. The model's own `gaps` field is ignored; `DrafterResult.gaps` is `gapsOf(body)`.
6. `DrafterInput.today` is a `Date` (the instant of the call). `DrafterInput` lives in core (`input.ts`) because the prompt file in `triage` cannot import from `replies`.
7. `usages`: one entry per attempt. The LLM client throws on an unreadable answer and gives no token count, so such an attempt gets an entry with zero tokens. Stage 07 writes an `llm.call` row for each entry.
8. A provider error (timeout, quota, bad key, blocked) throws `DrafterCallError { cause, usages }`; `usages` holds the finished attempts. It is not a `DrafterResult` (the stage type has only `checks` and `output`). Stage 07 maps `cause` with `llmErrorCode`. A non-LLM error goes up unchanged.
9. The retry runs once, after an unreadable answer or a failed check. A `no_draft` answer never retries. After a failed check and then an unreadable answer, the result is `failed` / `output`.

## Known limits (the code checks cannot see these)

- A number written in words, or digits split by letters, passes.
- An amount-shaped phone ("600 100 200,50") passes: the stage rule cuts amounts out first.
- `jan @ firma . pl` (spaces around the at sign) is not an address in the code; "jan at firma dot pl" is.
- Bare-domain detection uses a list of common top-level domains; `foo.zzz` with no scheme or `www.` passes.
- A confusable letter outside the small map can still hide a header name or a scheme.

## Race tests

Stage 01 has no DB, no job and no shared state. "One retry" is an in-process rule: `drafter.test.ts` runs two `draftReply` calls at once on one client and checks at most two LLM calls each and a different nonce for each request. The two-connection race tests for "exactly one / once" rules belong to stages 03 and 07 (the unique key of `reply_requests`, the one pair per request).

## Repair after review 1 (B1, B2, test gaps, invisible blank lines)

- **B1.** The number scan now has three steps: (1) IBAN on the uncut text; (2) a run of 13 or more digits, with valid calendar dates cut first but no amount cut; (3) the phone count (9–12 digits) after time and amount cuts. An account number next to `zł`, `PLN`, `EUR`, `USD`, `$`, `€` or `£` is `account_number`. Probe script: `/tmp/f115-s01/probe-account.ts` (1,975 forms, all flagged); legit forms: `probe-legit.ts`. Choices the stage text did not fix:
  - A date is cut only when it is a calendar date (day 1–31, month 1–12, year 1900–2199), so a range such as `18.11.2026 - 20.11.2026` is no account number and `12-34-5678 123` is still a phone.
  - The run allows spaces, line breaks, dots, dashes, slashes, underscores, brackets, pipes and a comma between two digits. A column of 13 or more digits on separate lines is therefore an account number (false positive, a retry).
  - The amount digit cap of the review is not needed: every run of 13 or more digits is gone before the amount cut, so an amount that reaches the cut has at most 12 digits.
  - The IBAN key stops at its last digit: a word after the number is no part of it.
  - A cut leaves ` ; `, so digits on both sides of a cut never join.
- **B2.** `draftCopyKey` and `DraftCopy` are in `packages/core/src/replies/copy-key.ts`. Text null stays `null` in the key (never equal to a real text; two null texts are equal, the baseline always has a text). The Subject has its white space collapsed. Stage 08 builds `draftCopyHash` on it.
- **Invisible blank lines:** U+2800, U+3164, U+FFA0, U+115F, U+1160, U+034F, U+17B4/5, U+180B–180F, U+FE00–FE0F, U+FFFC, U+00AD, U+200B–200F and U+2060–206F count as blank. They are no `control_chars` (except the format characters that were already).
- **Removed dead code:** the `hxxp` rule (the generic `scheme://` match already catches it) and the `｡` and `․` dot entries and two dash entries (NFKC already maps them).
- **New known limits:** digits split by letters or words in an account number; the review list N2 (phone `22.123.45.67`, newline-split phones, TLDs `.it .ch .at .es`, IDN, `https:\\evil.zzz`, `hxxps[:]//evil[.]zzz`, header-colon lookalikes, capital Cyrillic and Greek in header names, U+034F U+FE0F U+FFFC in text, four rounds of percent coding) is open for stage 02 and later. N1 (outcome per attempt in `usages`) and N3 (newlines of `fromName` and `subject` inside the block) are open for stage 07 and 02.
- **Mutation proof:** `/tmp/f115-s01/mutate2.py` runs 216 one-line mutants (log `/tmp/f115-s01/mutation2.log`, summary `/tmp/f115-s01/mutation2-summary.txt`); all fail a test, none is NOT-APPLIED.

## Re-repair after re-review 1 (B1-a, B1-b, test gaps, draftCopyKey)

- **One account view** (`entities.ts`, `accountNumbers`): the ASCII letter-and-digit groups of the text are joined into chains when 1–3 characters that are no letter and no digit lie between two groups (white space, line breaks, punctuation, symbols, marks; counted in code points). A letter of another script ends a chain ("zł", Polish words). The scan runs on the uncut text:
  - 13 or more digits in a chain is an account number. A run is exempt only when valid dates (day 1–31, month 1–12, year 1900–2199) and times cover ALL its digits (a date range is one exempt run).
  - An IBAN is a country code of the registry, two check digits, and the first characters that make 15 to 34 characters with 10 digits. It may start at a group start (the code may be a group of its own: `NL 91 ABNA`, `N L91`) or inside a group where the code and the check digits sit together (`kontoNL91ABNA…`). A word that ends with a country code and a separate group of digits (`dniach 15`, `jest 18`) is no start; nor is the end of a Polish word split by a letter such as `ł` (`Nakład` → `ad`). A lower-case code that is a group of its own and an ordinary word (`do no it is be at me so by mu ye`) is no start.
  - The scan has no list of separators and no amount cut. Dates, times and amounts are cut only for the phone count, after the accounts are cut.
- **Allowed account numbers** compare by key; a body key that starts with a typed account key is that number (the view joins a number with the group after it). The prefix rule is for `account_number` only.
- **Decisions**
  - The check digits of an IBAN shape are no longer exempted by a date (a French IBAN with a date at its start passed in a first try).
  - A letter-IBAN is found only when the code is not glued to a word that is not a currency AND split from its check digits (`plnNL 93 …`). A currency word glued before the number without a separator and with the code split from its digits is the one form that the random run does not generate (see the generator). Known limit.
  - `NUMBER` of an amount is one rule: digits, groups of 3 (space or dot), optional decimals of 1–2 digits.
  - False positives (accepted): a list of numbers with 13 or more digits in all, separated by commas or spaces, is an account number; a date followed by a number that makes 13 digits in all is one too.
- **draftCopyKey**: name and type are length-prefixed (`8:plan.pdf`), no name is `-`, To and Cc are sets (lower case, trimmed, no duplicate, sorted).
- **Blank lines**: `\p{Default_Ignorable_Code_Point}`, U+2800, U+FFFC, U+1D159 and U+16FE4 count as blank.
- **Proofs**: `/tmp/f115-s01/mutate3.py` runs 553 one-line mutants (every guard, every country code, every currency word and top-level domain, every entity and confusable); log `/tmp/f115-s01/mutation3.log`; all are killed. Random run: `/tmp/f115-s01/random-run.ts` (generator `packages/core/src/replies/random-accounts.test-helper.ts`): 5,000 accounts for each of PL NL DE GB FR NO KZ MT and 13–19 digit cards, 5,000 ordinary Polish sentences; logs `/tmp/f115-s01/random-run-*.log`.

## Re-repair 2 after re-review 2: the digit budget (owner decision "digit budget")

- **Design** (`packages/core/src/replies/digits.ts`, `checks.ts`): fold (NFKC, NFD, marks and default-ignorable characters out, ASCII digits) → every maximal digit run → KNOWN (3+ digits that are a substring of a typed number or of a 9–12 digit run of the quoted mail), FREE (valid date or time, month-in-words date, quarter, money with 2 decimals, percentage, rate, postal code, year 1900–2199, amount next to a currency) or it costs its digits. `account_number` when the cost is above 12 or a mod-97 IBAN that was not typed is in the body; `phone` when the unexplained digits make a phone-like run of 9 or more. The typed-prefix rule and the joiner code are gone. `checkReplyBody` takes `quoted`; `draftReply` passes the mail subject and body.
- **Choices beyond the owner text** (measured, not guessed): a number of the form of money, a percentage, a rate, a postal code or a year is free (without them 24.7 % of the reviewer's business bodies failed; with them 1.2 %); the free numbers of one body are capped at 40 digits; an amount next to a currency is free only when no unexplained digit run lies next to it in the same stretch without a letter; known runs have 3 or more digits; the mail keeps only runs of 9 to 12 digits; the phone rule keeps the spaced phone of the stage test 4.
- **Known limits**: a card of 13–16 digits has 1–4 digits of slack, so a group that looks like a date, year or rate can pass (about 7 % of random cards); an IBAN with 12 or fewer digits is found only by mod 97, so random check digits (reviewer generator `adv.ts`, 'raw ≤ 12 digits') and words between the groups pass; a letter group of 5 or more letters breaks the IBAN stream; a changed group of a typed phone number costs only its digits.
- **Equivalent mutants** (not run): the number of letters kept of a long word before a country code (2 or 3: only the code is read); a markup tag replaced by a space or by nothing (the stream ignores separators).
- **Last edit not re-mutated**: after the mutation run `/tmp/f115-s01/mutation4.log` (625 mutants, 611 killed, 14 survived) I removed lookarounds that were redundant (the run must lie inside the match), put the IBAN scan in the form `?? 0`, and added tests for the survivors (percent with 3 integer digits, the three lengths without a registry example). The survivors `iban: unknown country accepted`, `iban: the last start skipped` and the lookaround ones are covered by that edit, but the full mutation run was not repeated: unverified.
