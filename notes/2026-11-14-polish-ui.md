# Polish UI (F098): what a later agent needs

Rules live in `docs/code-patterns.md` § Texts carry a locale. This note holds what the code does not show quickly.

## Why the islands are client-only

Every island uses `client:only="react"`. The static build cannot know the language of the user. A server-rendered English island that hydrates with Polish text gives a hydration mismatch. Rejected: one build per language; English first, switch after mount (flash and errors).

## The `useLocale()` rule

The default export of each file in `apps/web/src/islands/` calls `useLocale()` on its first line. `t()` is a plain function that reads module state. Without the hook, a language change does not re-render the island. `apps/web/src/i18n/islands.test.ts` checks every island. A new island without the call fails that test.

## The placeholder inside approval views (D19)

`approvalViewOf` stores `sender.label` at queue time. For an unknown sender the stored value is the English text `"(unknown sender)"`. The approval renderer prints `texts.common.unknownSender` when the label equals that English value. The view schema did not change, so rows of the last 24 h still render. Do not change the stored value without a plan for those rows.

## The glossary

The Polish glossary (mailbox = skrzynka, mail = wiadomość, digest = podsumowanie, delegation = zlecenie, and so on) lives in `spec/features/active/F098-e7-t1-polish-ui-i18n-frame-first/plan.md` § Glossary. When the ticket moves to `done/`, the path moves with it. A docs page should take the glossary then.

## Deploy effects

- A user with no stored language (`users.locale` null) gets Polish Telegram text at once after stage 12 (owner decision, `docs/owner-decisions.md`). The panel does not: it follows the browser.
- Old cards queued before the deploy keep their English text. A tap adds a Polish status line on edit. The buttons Gotowe, Wysłano and "To był błąd" stay tappable for 7 days; the approval buttons stop after 48 h. So a mixed English card with a Polish line can show for up to 7 days.
- The Telegram command menu does not follow `users.locale`. Polling sets a default (English) list and a `language_code: "pl"` list; Telegram picks by the app language of the user.
- Operator notices, CLI output, logs, `deploy/` docs and outgoing mails to delegates stay as they were.

## Polish text rules (from the stage reviews)

Informal "ty". `pluralCategory(locale, count)` for every count (Polish `other` reads as `many`). At most one colon per line. One separator style (`·`). Names and addresses take no case ending.

## Activity phrases

`GET /api/activity` renders `aiText` and the phrases with `textsFor(resolveLocale(users.locale, firstLanguageTag(Accept-Language)))`. Browsers send `Accept-Language` with each `fetch`. No other route returns phrases of ours. Tests: `apps/server/test/integration/web-activity.test.ts` (user choice wins over the header).
