# F112 stage 05: CI job, deploy workflow, ADR (notes for stage 06 and later)

- `ci.yml` has a fourth job `docs` (checkout, Bun from `.bun-version`, Node 24, frozen install, `docs:build`, `docs:stale`; no services; `timeout-minutes: 20`). Stage 06 adds its browser check to this job. The file keeps `permissions: contents: read`.
- `.github/workflows/docs-deploy.yml` (never run, never tagged): jobs `build` and `deploy`. The workflow has `contents: read`; only `deploy` has `pages: write` and `id-token: write` and the environment `github-pages`. Actions: `checkout@v4`, `setup-bun@v2`, `setup-node@v4` (as `ci.yml`); `actions/upload-pages-artifact@v5` and `actions/deploy-pages@v5` (the current majors on 2026-11-15; `ci.yml`'s `checkout@v4` is older than the current `v7`, unchanged).
- Gate: `apps/docs/scripts/deploy-gate.ts` (`deployDecision`, `newestRelease`, `main`). The workflow step `gate` passes `GATE_EVENT`, `GATE_REF_TYPE`, `GATE_REF_NAME` as env (the github context never enters script text) and `git tag --list 'v*'` on stdin (`shell: bash` gives pipefail). It writes `deploy=true|false` to `$GITHUB_OUTPUT`; the job output `deploy` feeds `if:` of the `deploy` job and of every later `build` step. An `error` (bad event, ref type or empty name) exits 1; stage 13 adds its changelog error there. Only a plain `v<x.y.z>` tag counts (`vtest`, `v1`, `v0.2.0-rc.1` skip with "is not a release tag"); the pushed tag counts even if the tag list misses it.
- `DOCS_GIT_REF` is the tag name on a push and `github.sha` on a manual run. A manual run on an old tag therefore links to the commit, not the tag.
- Stage 12 adds the screenshot steps and the browser check to `build`: new steps must carry `if: steps.gate.outputs.deploy == 'true'` and stay before the upload; `workflows.test.ts` pins "3 steps after the gate" and will need that number changed.
- `apps/docs/scripts/workflows.test.ts` reads both workflows as YAML (`Bun.YAML.parse`): jobs, triggers, permissions (only `deploy` has Pages rights), environment, gate env, step order, `if` conditions, action pins, no secret, no `.env`. `deploy-gate.test.ts` holds T2–T6b plus the process run of the script.
- `docs:stale --strict` is in the deploy workflow, not in `docs/release-checklist.md` (stage 13 adds it there).
- ADR 0030 is now "accepted" with a "Built" section; `docs/architecture.md` has the docs app in the layout and a Deployment bullet; `docs/code-patterns.md` has § Docs site; `docs/capabilities/README.md` names `apps/docs/src/content/docs/`.
