# F112 stage 06: browser check (notes for stage 07 and later)

- `bun run docs:test` = Playwright on the built site: `apps/docs/e2e/` (`playwright.config.ts`, `serve.ts`, `site.ts`, `a11y.ts`, `site.spec.ts`). One project, desktop Chromium 1280×800, `CHROMIUM_PATH` as in the panel config. Needs `bun run docs:build` first. Run it under `flock /tmp/email-assistant-shared-tests.lock` (port 8093 is fixed; `reuseExistingServer` is false, so a taken port fails).
- Page list: `builtPagePaths()` reads the `.html` files of `dist` (an `index.html` is its folder with a trailing `/`; `404.html` is not a page). A new page needs no edit. Tests: T1 (CSP violations and page errors) and T4 (axe) run once per page; T2 search (button and Ctrl+K), T3 `lang`, T5 404 page run once.
- Env `DOCS_TEST_URL=<origin>` (stage 16): the tests open that site and start no server; the page list still comes from local `dist`. Env `EA_DOCS_DIST_DIR` points everything at another folder (tests only).
- Missing build: with the local server, `serve.ts` exits 1 with "run `bun run docs:build` first" and Playwright reports the server as not started. With `DOCS_TEST_URL` the spec throws "dist/index.html is missing: run `bun run docs:build` before `bun run docs:test`".
- axe found one real problem in Starlight 0.43.1 on every page at desktop width: `label-content-name-mismatch` (WCAG 2.5.3) on the search button (`aria-label="Search"`, visible text is the keyboard hint "Ctrl K"). CSS fix, default taken (plan N4 asked for config or CSS first): `apps/docs/src/styles/custom.css` (Starlight `customCss`) hides `site-search kbd` with `!important` (a script sets the inline style). The hint is gone, the shortcut stays (`aria-keyshortcuts`; T2 presses Ctrl+K). The owner may prefer the hint and an override of Starlight's `Search` component instead. No axe rule is disabled. The narrow viewport had no violation before the fix.
- The unit tests are `apps/docs/scripts/browser-check.test.ts` (server, page list, config, wiring, pinned versions, `.gitignore`) and a new test in `workflows.test.ts` (CI steps: install Chromium, `docs:test`, upload on failure, 7 days). They sit in `scripts/` because `bun test` would run `*.spec.ts` in `e2e/` as unit tests; `test:unit` lists no `e2e` folder.
- CI `docs` job: after `docs:stale`: `bunx playwright install --with-deps chromium`, `bun run docs:test`, upload `apps/docs/e2e/test-results/` (7 days, name `docs-playwright-results`) on failure. Not run on GitHub (nothing in this repo pushes). Stage 12's deploy-workflow browser check can reuse `docs:test`.
- `apps/docs/package.json` has `@playwright/test` `1.65.0` and `@axe-core/playwright` `4.14.0` (the panel's pins); `bun.lock` changed by those two lines only. Firefox and Safari stay out of scope (plan N2 open).
- Not run: the server image build (T7): this stage adds no file to the image (Docker build not run here; the image install skips `@ea/docs` and `workflows.test.ts`/stage 01 checks are unchanged).
- Mutation run: `/tmp/f112-s06/mutate.py unit|dist`, summary `/tmp/f112-s06/mutation-summary.log` (53 source guards: server, page list, config, scripts, pins, `.gitignore`, CSS, CI wiring; 9 `dist` mutations through `EA_DOCS_DIST_DIR`: CSP, page error, search, both `lang`, axe, 404, list).
