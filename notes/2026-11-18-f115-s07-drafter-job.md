# F115 stage 07: the drafter job (2026-11-18)

What a later agent needs. Stage file: `spec/features/active/F115-e6a-reply-drafts/stages/stage-07-drafter-job.md`. Behaviour rules: `docs/capabilities/drafts-and-send.md` rule 16, bullet "Drafter job".

## Where the code is

- `apps/server/src/modules/replies/jobs.ts`: `createReplyJobs(deps)` → `drafter.run({ mailboxId? })`. Scan, claim, per-request loop. Registered in `main.ts` (`replies.drafter`, every 15 s, inside the `TRIAGE_LLM_SCOPE` block) and in `scripts/job-run.ts` (`bun run job:run --name replies.drafter`).
- `draft-one.ts`: one request, in the order of the stage file (timeout, try limit, stored result, redraft pre-check, facts and gates, scope, recipient, no text, cap, call, outcome). `recoverRequest` for a database error or a bug after the claim.
- `write.ts`: the ONE write transaction (settings share lock, thread advisory lock, request row under the claim token, gates and facts again, thread rule, pair, end of request; redraft through `replaceApproval`).
- `spend.ts`: `capVerdict` (80 % wait for `auto`, 100 % `llm_cap`, `maxCalls` from what is left) and `recordAttempts` (one `llm.call` row per call, own commit).
- `repo/scan.ts` (scan, test-mail check, mail text read), `repo/requests.ts` (`lockReplyRequest`, `failStaleUserRequests`, `triggerOf`).
- Other modules: `actions/repo/reply-threads.ts` (`listOpenReplySendsOfThread`), `findSendByKey` exported, `tenancy.getOrgOwner` (name and locale).

## Choices made here (defaults, none needs the owner)

- **Spend.** The only LLM limit in the code is the per-mailbox daily cap (`LLM_DAILY_CAP`, all roles, quota day). There is no per-organization LLM limit; the organization is covered by the suspended check, the flag, the scope and the LLM pause. `draftReply` takes `maxCalls`: with one call left under the cap the retry does not run, so the day never passes the cap by the retry.
- **Crash after the call.** The answer is not stored (no column for it; no migration). A crash or a failed write repeats the call and never the draft (two `llm.call` rows, one pair). A stored result that exists (the pair with the key `<request id>:send`) is found before the call: no call, no pay. Three guards stop a second pair: the claim token under the row lock, the idempotency keys, the pre-call check.
- **Per-call audit rows (stage 01 N1).** `DrafterResult.attempts` replaces `usages`: each call has `outcome` (`ok`, `bad_output` or the LLM error code), `usage` (null when none) and `latencyMs`. A provider error is in `DrafterCallError.attempts` as the last entry. Every call writes a row, so the cap counts failed calls.
- **Soft errors count no try** (as the stage says), so an `auto` request with a mail that always times out retries every 5 minutes until the mail is older than 7 days or the 80 % line holds. Each retry costs a `llm.call` row. If this shows in the logs, count `timeout` as a try like `loops.analyze` does.
- **Reason codes of a request (stage 12, 13, 14 read them).** `cancelled`: the `replyEligibility` reasons, `feature_off`, `switch_off`, `not_assist`, `oauth_mailbox`, `llm_scope`, `bad_recipient`, `mail_gone`, `answered`, `suspicious` (the last two also at the write), `closed` and `changed` (redraft). `failed`: `timeout`, `llm_cap`, `llm_error`, `checks`, `output`, `internal`. `no_draft`: `needs_facts`, `not_a_reply`, `unsafe_request`, `no_text`. `superseded`: `open_newer`, and `send_action_id` holds the open send.
- **Redraft.** The job calls `replaceApproval` with `via: "web"` and the requester as `userId` (`system` when the user is gone): the cards of every owner are edited, none is skipped. The request has no channel column. `body_text` (the user's edit) is dropped with the old version.
- **The thread rule is only about open replies.** A newer mail in the thread that has no open reply does not stop a request. Stage 09 (`newerMailInThread` in the sweep) closes such a draft; until then a draft for the older mail can exist next to a newer unanswered mail.
- **Sample requests** (stage 16 makes them) skip the mode, the switch and the thread rule and store `sample_body`. The flag, the scope, the eligibility and the cap still apply.
- **Prompt (stage 01 N3).** `drafter-v1` builds the `From:` and `Subject:` lines of the data block as one line (`oneLine`). The system text did not change. No gate file or eval changed: `drafter-v1` has no real run yet (stage 02 waits for the key), so no gate evidence moved.
- **N2 of stage 01** (known false negatives of the checks) is not a stage 07 item: it stays for stage 02 and later. The job runs the checks of core on every answer; a failing draft ends `failed` / `checks` and is never stored.
- **GreenMail.** The stage text says GreenMail for the committer step. The tests use the in-memory fake provider (`createFakeMailProvider`), as every committer test does, inside a rolled-back transaction. The IMAP contract tests cover the real server.
