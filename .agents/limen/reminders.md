- A job that commits product code (slice, repair, finish, continue; not a review, plan, scout, research or quality job): the last step before the final message is `git merge --no-edit master`, then `bun run typecheck && bun run lint && bun run test:unit:ci` and the lane of the tests this job changed, then a commit. A failure after the merge is this job's work: fix it, run the checks again, commit. The final message names the master SHA you merged and the real result of each check. The coordinator lands your branch without a new test when master did not move after that merge (owner rule 2026-11-20, `notes/2026-11-20-coordinator-waits.md`).
- `bun run lint` and `bun run typecheck` keep a cache in `node_modules/.cache/` (owner 2026-11-20): a second run checks only what changed, in seconds. Run them in the foreground; never delete that folder. `bun run lint:full` lints with no cache (CI and the land check run it).
- While you work, run `bun run test:unit:changed` (owner 2026-11-20): only the unit tests that import a file this branch changed, in seconds. It does not see a changed shell script or a data file read at run time, so run the full `bun run test:unit:ci` once, in the last step above.
