# F156 questions

1. [important: production] **Stored drafts that hold an impossible due date: no migration.** After the change, a stored `delegation` or `reminder` draft with a date such as `2026-02-30` no longer parses: its approval card fails like any other invalid payload. Such a row exists only if the classifier wrote such a date. Default (plan.md D5): no migration; the coordinator counts these rows on production after the release (read-only) and opens a follow-up ticket when the count is above zero. Other options: (a) a data migration now that sets those `due_date` values to `""`; (b) a read-side fallback in every reader. Undo: write the follow-up ticket with option (a).
2. [minor] **An impossible LLM date becomes "no date".** The planner writes `""` for a classifier date that is not on the calendar (plan.md D2), so the draft is still made and the message has no due line. This matches the current delegation rule "A date that does not exist gives no date". Option: drop the delegation draft instead. Undo: change `dueDateOrNone` callers.
