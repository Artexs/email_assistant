# F086 · Module borders are linted: layers, allowed edges, no deep imports, a generated module graph

## Outcome

A server module can import only the `index.ts` of a module in a lower layer, and ESLint fails on anything else. The two borders that are broken today are repaired. `docs/modules.md` §2 shows a module graph that a script generates from the code, so it cannot drift. The code standards of the architecture review are in `docs/code-patterns.md` and the styleguide, so every Stage 2 planning session and worker reads them.

## Scope

- Starting seam: `eslint.config.js` (the `nodeConfig` block and the `restrictImports` pattern), `apps/server/src/modules/*/index.ts`.
- The two violations: `apps/server/src/modules/actions/repo.ts:14` (imports `../delegation/repo`) and `apps/server/src/modules/config/service.ts:19` (imports the type `ExpireFilter` from `../actions`).
- A layer list and an allowed-edge list as data, one generated graph file, one test that compares the code with the list.
- The standards of `docs/product/stage-2/06-architecture-review.md` §7 that apply today, in `docs/code-patterns.md` and `.agents/limen/styleguide.md`. Standards that need a seam that does not exist yet (flags, notice facts, LLM roles, log events) are added by the ticket that builds the seam.

## Out of scope

- Splitting the big repository files (F091). Any behaviour change.
- Cycles inside one module (`apply.ts` ↔ `drafts.ts`, `llm/client.ts` ↔ `providers/`): list them in the plan, fix only if the lint needs it.

## Acceptance

- `bun run lint` fails on a deep import (`../<module>/<file>`); a fixture proves it.
- `bun run lint` fails on an import from a higher layer; a fixture proves it.
- `bun run lint` fails on a cycle between two modules; a fixture proves it.
- `actions` no longer imports from `delegation`; `config` no longer imports from `actions`; `madge --circular` reports no cycle across modules.
- `docs/diagrams/module-graph.md` is generated by `bun run graph:modules` and a unit test fails when the code has an edge that the allowed list lacks.
- `docs/code-patterns.md` and the styleguide hold the layer list and the standards; `docs/modules.md` §2 links the generated graph instead of its hand-drawn one.
