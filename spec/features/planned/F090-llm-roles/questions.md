# F090 · Open questions (small: the stages do not change with the answer)

Each has a default that the plan uses now. Answer only to change one.

1. **Does the classifier get its own `LLM_CLASSIFIER_*` keys?** Default: no. The classifier keeps today's keys (`LLM_PROVIDER`, `OPENAI_MODEL_CLASSIFIER` or `GEMINI_MODEL_CLASSIFIER`, the provider's timeout and effort), so there is one key per setting and the VPS `.env` does not change. The four other roles get `LLM_<ROLE>_PROVIDER`, `_MODEL`, `_TIMEOUT_MS`, `_RPM`, `_REASONING`. (plan.md D9)
2. **Must a role's provider key exist at start?** When `LLM_JUDGE_PROVIDER=gemini` is set and `GEMINI_API_KEY` is empty, the server refuses to start and names the key. The same for a reasoning key on Gemini, which takes no effort. Default: yes, refuse at start, so a wrong role setting shows at once and not at the first judge call weeks later. (D11)
3. **What does "the classifier tests pass unchanged" allow?** The client interface changes (`generate` and `modelOf` instead of `classify` and `classifierModel`), so every test's fake LLM client changes shape. Default: test names, inputs and assertions stay; only the fakes and their usage fixtures change; one assertion gains `role: "classifier"` on purpose (the `llm.call` data in `triage-service.test.ts`). (D17)
4. **What does `llm:check --role judge` send before the judge has a prompt?** Default: one small greeting call on the judge's provider and model (it proves the key, the model and the route); the classifier keeps its triage checks. The epic that writes the judge prompt adds a judge sample check. (D23)
5. **Does `eval` get a `--role` flag?** Default: no. Only the classifier has an eval set; both eval reports now say `- role: classifier`. E2a adds role sets and the flag. (D24)
6. **Remove the unused writer keys `GEMINI_MODEL` and `OPENAI_MODEL`?** No code reads them (the S4 writer role was never built; drafts are templates). The drafter role takes over with `LLM_DRAFTER_MODEL`. Default: remove them from the config, `.env.example` and the docs in stage 5. A `.env` that still has them keeps loading. (D25)
