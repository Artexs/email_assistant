## Step 1 — The migration

**Goal.** One dbmate file that adds both tables with their checks, indexes and the `tenant_rows` policy.

**Files.** `db/migrations/<YYYYMMDDHHMMSS>_sent_mail.sql` (new; the timestamp is later than the newest file in `db/migrations/` at your base, `20261114110001` at the plan base), `apps/server/src/platform/db/schema.ts` (generated by `bun run db:types`, never by hand).

**Interfaces.** The `up` part, exactly (the column order is free):

```sql
-- migrate:up
-- The user's sent mail, read read-only from the Sent folder (ADR 0029). Never triaged, never moved.
CREATE TABLE sent_emails (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id uuid NOT NULL,
  mailbox_id uuid NOT NULL,
  dedup_key text NOT NULL,
  uidvalidity bigint NOT NULL,
  uid bigint NOT NULL,
  message_id text,
  parent_message_id text,
  references_ids text[] NOT NULL DEFAULT '{}',
  thread_key text NOT NULL,
  from_address text,
  to_addresses text[] NOT NULL DEFAULT '{}',
  cc_addresses text[] NOT NULL DEFAULT '{}',
  subject text,
  sent_at timestamptz NOT NULL,
  internal_date timestamptz NOT NULL,
  action_id uuid,
  content text NOT NULL CHECK (content IN ('pending', 'stored', 'headers_only', 'gone')),
  body_text text,
  auto_submitted text,
  precedence text,
  list_id text,
  has_calendar boolean,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (mailbox_id, org_id) REFERENCES mailboxes (id, org_id) ON DELETE CASCADE,
  UNIQUE (mailbox_id, dedup_key),
  UNIQUE (id, org_id),
  -- A system send (its X-EA-Action-Id is an action of this mailbox) never gets text.
  CONSTRAINT sent_emails_system_check CHECK (action_id IS NULL OR content = 'headers_only'),
  CONSTRAINT sent_emails_body_check CHECK (body_text IS NULL OR content = 'stored')
);
CREATE INDEX sent_emails_org_id_idx ON sent_emails (org_id);
CREATE INDEX sent_emails_org_internal_idx ON sent_emails (org_id, internal_date);
CREATE INDEX sent_emails_parent_idx ON sent_emails (mailbox_id, parent_message_id)
  WHERE parent_message_id IS NOT NULL AND action_id IS NULL;
CREATE INDEX sent_emails_thread_idx ON sent_emails (mailbox_id, thread_key);
CREATE INDEX sent_emails_user_idx ON sent_emails (mailbox_id, internal_date) WHERE action_id IS NULL;
CREATE INDEX sent_emails_pending_idx ON sent_emails (mailbox_id, internal_date) WHERE content = 'pending';

-- One row per mailbox: the "Track my sent mail" switch, the Sent path and its cursor. No row = off.
CREATE TABLE mailbox_sent_sync (
  mailbox_id uuid PRIMARY KEY,
  org_id uuid NOT NULL,
  enabled boolean NOT NULL DEFAULT false,
  enabled_at timestamptz,
  path text CHECK (path IS NULL OR length(path) BETWEEN 1 AND 200),
  uidvalidity bigint,
  last_uid bigint,
  first_pass_at timestamptz,
  last_pass_at timestamptz,
  last_error_code text CHECK (last_error_code IS NULL OR last_error_code IN ('no_folder', 'folder_missing', 'failed')),
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (mailbox_id, org_id) REFERENCES mailboxes (id, org_id) ON DELETE CASCADE,
  CONSTRAINT mailbox_sent_sync_enabled_check CHECK (enabled = (enabled_at IS NOT NULL)),
  CONSTRAINT mailbox_sent_sync_cursor_check CHECK ((uidvalidity IS NULL) = (last_uid IS NULL)),
  CONSTRAINT mailbox_sent_sync_off_check CHECK (
    enabled OR (path IS NULL AND uidvalidity IS NULL AND first_pass_at IS NULL AND last_pass_at IS NULL AND last_error_code IS NULL)
  )
);
CREATE INDEX mailbox_sent_sync_org_id_idx ON mailbox_sent_sync (org_id);
```

Then the RLS block for each table, copied from `db/migrations/20261114100002_rls_tenant_policies.sql` (the `emails` block is the model):

```sql
ALTER TABLE sent_emails ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_rows ON sent_emails FOR ALL TO app
  USING (app_current_org() IS NULL OR org_id = app_current_org())
  WITH CHECK (app_current_org() IS NULL OR org_id = app_current_org());
```

and the same for `mailbox_sent_sync`. Add no `GRANT`: the default privileges of `20261103000001_app_grants.sql` give `app` SELECT, INSERT, UPDATE and DELETE on every new table (no newer table migration has a `GRANT`). The `down` part: `DROP POLICY tenant_rows ON …` and `DROP TABLE …` for both, `mailbox_sent_sync` first.

Then `bun run db:migrate` on the job DB and `bun run db:types`.

**Decisions.** D1, D2, D6, D7 (the `content` states), D14 (the index on `internal_date`).

**Test.** Step 2.

**Check.** `bun run db:migrate && bun run db:types && git diff --stat apps/server/src/platform/db/schema.ts` (the two tables appear); `bun run db:rollback && bun run db:migrate` (down and up both run).

**Done when.** Both directions run; `schema.ts` has `SentEmails` and `MailboxSentSync`.

**Out of scope.** Any repository function (stage 02). The outbox kind (stage 09).

## Step 2 — Schema tests and the shared test fixtures

**Goal.** Tests that pin the checks, the cascade and the RLS policy, and the two tables in the shared mailbox fixtures.

**Files.** `apps/server/test/integration/mail-schema.test.ts` (new `describe("sent mail")`), `apps/server/test/integration/rls-policy.test.ts` (`TENANT_TABLES` and `seedOrg`), `apps/server/test/integration/mailbox-rows.ts` (`fillMailbox`, `countMailboxRows`), `apps/server/test/integration/delete-mailbox.test.ts` and `mail-remove.test.ts` only where an expected object lists the counts by hand.

**Interfaces.** In the tests, insert rows with plain Kysely (`trx.insertInto("sent_emails").values({...})`); the repository comes in stage 02. A minimal sent row: `{ org_id, mailbox_id, dedup_key: "mid:<a@x.test>:h1", uidvalidity: 7, uid: 1, thread_key: "<a@x.test>", sent_at: NOW, internal_date: NOW, content: "pending" }`.

- `fillMailbox` inserts one `sent_emails` row and one `mailbox_sent_sync` row (`enabled: true, enabled_at: now`) for the mailbox.
- `countMailboxRows` returns two more keys, `sent_emails` and `mailbox_sent_sync` (count by `org_id` and `mailbox_id`, like `byMailbox`).
- `rls-policy.test.ts`: add `"mailbox_sent_sync"` and `"sent_emails"` to `TENANT_TABLES` in alphabetical order; `seedOrg` already calls `fillMailbox`, so it gets rows for both.

**Decisions.** D1, D2.

**Test** (integration, `withRollback`, `NOW = 2026-11-20T10:00:00Z`):

1. A minimal `sent_emails` row inserts; `references_ids`, `to_addresses`, `cc_addresses` default to `{}`.
2. A `sent_emails` row with the mailbox of org A and the `org_id` of org B fails with `23503`.
3. Two rows with the same `(mailbox_id, dedup_key)` fail with `23505`; the same key in another mailbox inserts.
4. `content = 'new'` fails with `23514`.
5. `action_id` set and `content = 'pending'` fails with `23514` (`sent_emails_system_check`); `action_id` set and `content = 'headers_only'` inserts.
6. `body_text = 'x'` and `content = 'pending'` fails with `23514`; with `content = 'stored'` it inserts.
7. `mailbox_sent_sync` with `enabled = true` and `enabled_at` null fails with `23514`; with `enabled = false` and `last_uid = 5, uidvalidity = 7` fails with `23514`; `uidvalidity` set and `last_uid` null fails with `23514`; `last_error_code = 'other'` fails with `23514`.
8. Deleting the mailbox deletes its `sent_emails` and `mailbox_sent_sync` rows (count 0 after).
9. The RLS test passes with both tables in `TENANT_TABLES` (policy text and the scoped read return no row of the other org).
10. The delete-mailbox tests pass with the two new count keys (the deleted mailbox has 0, the others keep 1).

**Check.** `bun test apps/server/test/integration/mail-schema.test.ts apps/server/test/integration/rls-policy.test.ts apps/server/test/integration/delete-mailbox.test.ts apps/server/test/integration/mail-remove.test.ts`

**Done when.** Cases 1–10 pass.

**Out of scope.** Tenant-filter tests of repository functions (stage 02).
