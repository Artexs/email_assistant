# F113 questions (defaults taken; none blocks the stages)

1. **Q1 [important: money] Which OpenAI key does the sim stack use?** Default: the production key of the VPS `.env`, copied into `deploy/sim.env` by the coordinator without printing it (runbook step 4). The lab caps its own spend ($1 a day run, $5 a week run; D12) and counts in the $20 month cap of the ledger on the VPS. Other option: a separate OpenAI project key for the lab (owner step: make the key; the coordinator puts it in `sim.env`). Change: none in code.
2. **Q2 [important: production] The sim stack runs on the production VPS.** Default: a second Compose project with its own port (8180), subnet (`172.31.0.0/24`), volumes, memory limits (about 1.5 GB total) and env file; the production stack is not touched. A live day may run before the disk step O1 when at least 2 GB are free; the live week waits for O1 (PD-055). Other option: run the sim stack only on the owner's PC (PD-020 fallback; it needs the owner's Docker access, because agents cannot use the local Docker socket). Change: C1–C6 move to the owner's PC.
3. **Q3 [important: scope] Dates in mail text move with the run.** Default: full dates move by the run's whole-week offset; bare years, month-and-year ("January 2027") and ids stay (D6). Without it the urgent truth of deadline mail breaks. Other option: run the week only on its scenario dates (2027-01-25), with no text change. Change: stage 01 drops the rewrite; live days are then not possible before 2027.
4. **Q4 [important: scope] No "not mine" delegate answer, no new phishing corpus.** Default: the five behaviours of the frozen corpus only; wrong-person mistakes come from the executive's reject reason (D10). The phishing set with more personas and `Authentication-Results` (named as "E2b's" in the F109 stage 06 notes) is not in F113: F113 writes no corpus text. Other option: a corpus v1.1 with a `not_mine` behaviour and a phishing extension (new writer and checker batches, a new owner audit). Change: a new ticket.
5. **Q5 [important: security] The fake Telegram shares one network namespace with the sim server.** Default: `server` and `lab` join the fake's namespace, so the loopback rule on `TELEGRAM_API_ROOT` stays as it is (D1). Other option: a bind option on the fake and a config key that allows a private-network Telegram root. Change: stage 03 network, `platform/config.ts`.
6. **Q6 [minor] What the executive taps.** Default: approve, reject with reason, Undo of a wrong move, reminder sets, send again once; no relabel taps, no draft edits (Telegram has no draft edit; the E4-A panel commands come later). Stage 09.
7. **Q7 [minor] Run calendar.** Default: a day run plays the scenario day with the same weekday, from tomorrow; a week run starts on a Monday; tails of 1 day (day) and 4 days (week). Stages 01, 05.
8. **Q8 [minor] No draft judge in the live report.** Default: the live report scores drafts by the executive's approve or reject only; the E2a judge covers draft text offline. Other option: a `--judge` flag on `lab score` (Gemini key needed on the VPS).
9. **Q9 [minor] Prior history and urgency profile.** Default: `week/history.json` is not seeded (E11a may add a seeder); the urgency profile is stored only when the E3b store exists (D18).
10. **Q10 [minor] Demo import safety.** Default: the imported demo org has a paused mailbox, open actions `expired`, no Telegram link; a seed file is committed by the coordinator only when it is under 5 MB, else it stays a local file for F121. Stage 15, C6.
11. **Q11 [minor] Month cap on two machines.** Default: the lab's month cap reads the ledger on the VPS (in the lab volume); offline evals on the owner's PC use their own ledger, so the $20 cap is per machine. Other option: one shared ledger (a file the coordinator syncs). Stage 11.
12. **Q12 [minor] Executive taps are at most once.** Default: after a crash between a tap's intent and its done event, the executive does not press again (`skip tap_unsure`); the report shows the lost tap. Other option: per-button DB checks before a second press. Stage 10 (review 1, T8).
13. **Q13 [minor] Each measured run starts on a fresh lab organization.** Default: `start` refuses an org that holds mail (`org_not_fresh`) unless `--reuse`; `lab reset --org lab` rebuilds it, so metrics of an older run never mix in. Stages 05, 14 (review 1, T10).
