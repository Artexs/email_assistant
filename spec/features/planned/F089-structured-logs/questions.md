# F089 · Open defaults for the owner

The planning job (2026-11-13) took these defaults. None of them changes the stages. Answer any of them before the stage that uses it; no answer = the default stays.

| #   | Question                                                                                                  | Default (decision in `plan.md`)                                                                                                                                                                       | Used in   |
| --- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| Q1  | Does `msg` get its own readable text, or equal the event code?                                            | `msg` equals the event code. A message table is a later change (D9).                                                                                                                                   | stage 01  |
| Q2  | Is the lint `warn` everywhere until E8a ends, or `error` for files that are already converted?            | `error` for `platform/` and `main.ts` after stage 06, `warn` for the rest. So nobody adds an old-form line to a converted file (D18).                                                                   | stage 06  |
| Q3  | Does `deploy/compose.yaml` pin `LOG_FORMAT: json`?                                                        | Yes. `.env.example` sets `text` for dev, and a new install copies `.env.example`; the pin keeps the VPS on JSON (D21). Plan input D5 said "compose sets nothing".                                       | stage 02  |
| Q4  | Which incoming `x-request-id` values does the server reuse?                                               | Only a UUID, and only from a peer in `WEB_TRUSTED_PROXIES`. Any other value gets a new UUID (D17).                                                                                                     | stage 03  |
| Q5  | How does an error reach an event line?                                                                    | `...errorFields(error)`: two fields, `error` (the name) and `error_code`. D6's `{ code: describeError(error) }` would always be dropped, because its value has a space (D14).                            | stage 01  |
| Q6  | What happens to the text that Better Auth logs?                                                           | A fixed table maps the known texts to a `reason` code; any other text becomes `reason=other`. The library text no longer reaches the log (D20).                                                        | stage 05  |
| Q7  | Does the text form show the context ids?                                                                  | Yes: `[mail] sync_done job=mail.sync run_id=… count=3` (D12).                                                                                                                                         | stage 01  |
| Q8  | In `json`, what happens to the old-form lines of the modules until E8a converts them?                     | They become `{ …, "event": "legacy_text", "msg": "<the old text>" }` with the context ids. Nothing new leaks: it is the text they print today (D10).                                                    | stage 01  |
| Q9  | Is a URL allowed as a field value?                                                                        | No: a value with `://` is dropped. The heartbeat URL is a secret token (D7).                                                                                                                          | stage 01  |
