# F117 questions (defaults taken, owner to confirm)

No blocking question. Each item: the question, the default the plan uses, and why.

- **Q1 [important: security]** ADR 0031 says the access token lives in memory "for one job". Default: a process cache of access tokens per mailbox and resource, used while 5 minutes or more remain, dropped at Reconnect, Remove and a refused login (D14). Why: Microsoft rotates the refresh token at each redeem; a refresh per sync run (every 2 min) means about 720 locked DB writes per mailbox per day and more rotation races. The token stays in process memory only. Stage 19 writes it into ADR 0031 as an amendment.
- **Q2 [important: user-visible]** What do the flags `mail_oauth_microsoft` and `mail_oauth_google` gate? Default: a new connect only. Reconnect and existing OAuth mailboxes keep working with the flag off (D8). Why: a flag turned off must not strand a connected mailbox in `auth_error` with no way out.
- **Q3 [minor]** Can a password mailbox (for example the Gmail app-password preset) switch to OAuth in place? Default: no. The owner removes it and connects with Google; the history of that mailbox goes. Why: smaller first build; PD-087 keeps the app-password path as the durable one for personal Gmail.
- **Q4 [important: user-visible]** Microsoft admin consent needs a registered redirect page. The panel is tailnet-only (ADR 0017), so an administrator outside the tailnet sees a browser error after the approval. Default: the page `/mailboxes/admin-consent` on the panel, and a caveat text next to the link ("The approval still counts"). Why: a public page is an ADR 0017 change (E7/E10).
- **Q5 [minor]** Microsoft tenants that still allow SMTP AUTH: send through SMTP or Graph? Default: Graph for every Microsoft mailbox (D5). Why: one send path for Microsoft; security defaults turn SMTP AUTH off (R2), so most tenants need Graph anyway.
- **Q6 [important: privacy]** Does an organization delete (the account-data ticket, F106) revoke Google tokens? Default: no; the tokens are deleted with the rows, so we keep no access. The single mailbox Remove revokes (D19). Why: the delete path of F106 is built and tested; a revoke there adds outside calls to a destructive transaction.
- **Q7 [minor]** Which 20 cases does the provider smoke append? Default: 15 from `evals/cases/synthetic.json` (3 per category) and 5 from `delegation.json` (stage 20). A frozen E2a bank (the offline-lab ticket, F097) can replace it later; never its holdout part. Why: the bank is not frozen at the plan base.
- **Q8 [important: security]** The ID token from the token endpoint: check its signature? Default: no; check `aud`, `exp`, `iss` and (Google) `email_verified` (D12). Why: OpenID Connect Core 1.0 §3.1.3.7 rule 6 allows TLS server validation in place of the signature for a token got directly from the token endpoint; no JWKS fetch, no key cache.
- **Q9 [minor]** `TEST_MAILBOX_ADDRESS` holds one address today; the smoke needs two test mailboxes. Default: a comma-separated list; one address works as before (stage 20).
- **Q10 [minor]** Google answers `invalid_grant` for an expired and for a revoked grant alike. Default: the reason is `oauth_expired` (the 7-day testing-mode end is the common case). The text says "expired, tap Reconnect", which also fixes a revoke.
- **Q11 [minor]** PD-088 says one OAuth app per provider per deployment. The owner has two hosts (dev and VPS). Default: the owner's own Entra app and Google client hold the redirect URIs of both hosts; a customer who hosts a copy registers their own apps (stage 19 doc).
