# F144 close-out: open test gaps

Written by the stage 06 worker. The reviewers of stages 02 to 05 named gaps in the isolating power of the tests. Each is recorded here with what was done.

1. **Two alias filters, proven only together.** `ownAddressesOf` (`mail/repo/sender-activity.ts`) and `senderWindow` each filter a missing and a blank address. Done: `mail-sender-activity.test.ts` tests 7b and 11 prove the blank filter alone (guard checks: removing it fails the test). Not isolatable: the `is not null` filter. A null column fails `<> ''` and `btrim(...) <> ''` as well (three-valued logic), so the null filter is redundant and no test can fail on it alone. A later change may drop it.
2. **`org_id` joins on `email_flags` and `email_headers`.** Not isolatable by a test. Both tables have `PRIMARY KEY (email_id)` and `FOREIGN KEY (email_id, org_id) REFERENCES emails (id, org_id)`. A row of another organization cannot point at a window mail of this one, so removing `f.org_id` or `h.org_id` changes no result. The filters stay as a guard against a later change of those keys.
3. **Window and reader `org_id` filters of stages 04 and 05, proven only in pairs.** The window filter `emails.org_id` and the reader filter `tr.org_id` (triage) cover each other: with org A's context and org B's mailbox id, one filter alone keeps the result empty. Seen: removing `emails.org_id` fails only `mail-sender-activity.test.ts` test 4, while both triage tenant tests still pass (`/tmp/f144s06/guard-window-orgid.log`). So the window filter is proven by the mail reader test; the `tr.org_id`, `tf.org_id`, `s.org_id` and `dn.org_id` filters are not isolatable by a test, because `triage_results`, `triage_feedback`, `sent_emails` and `delegations` carry composite foreign keys `(…_id, org_id)` to `emails`, `mailboxes` and `delegates`: a row cannot name another organization's mail or mailbox. Delegations: removing `dn.org_id` fails test 4 of `delegation-activity-repo.test.ts` (`/tmp/f144s06/guard-orgid.log`); the `d.org_id = dn.org_id` join term is not isolatable for the same reason.
