## Stage 18 — Eval report and CLI [risky]

- [x] **18.1 `renderEvalReport` and `bun run eval`**
  - Goal: one command that runs the eval on the synthetic and injection sets and prints the Markdown report and the go/no-go table.
  - Files: create `apps/server/src/modules/triage/eval-report.ts`, `apps/server/src/modules/triage/eval-report.test.ts`, `apps/server/src/scripts/eval.ts`; export `renderEvalReport` and `evalExitCode` from `triage/index.ts`; change root `package.json` (`"eval": "bun apps/server/src/scripts/eval.ts"`).
  - Interfaces:
    - `renderEvalReport(report: EvalReport, opts?: { title?: string }): string` (Markdown).
    - `evalExitCode(report: EvalReport): 0 | 1` (step 30.1 adds `2`).
    - CLI: `bun run eval [--model <id>] [--set synthetic|injection|all] [--bar 0.98] [--min-kept 30] [--retries 4] [--limit n] [--out <file.md>]`. Default model: `classifierModel(config)`. Needs `GEMINI_API_KEY`. `--limit n` = the first `n` cases by `id` after the set filter (smoke runs).
  - Decisions:
    - `renderEvalReport` rules by `report.kind` (review finding 15). Parts, in this order:
      1. Header. `cases`: date, model, prompt version, case counts per set, bar, minimum support, and the line "no generation settings: results can change between runs". `real`: date, "N labeled real mails" (`labeled`), the mail kind when it is `synthetic` ("synthetic mail, dev check"), rule count, error count, bar, minimum support, and when `labeled` < 100 the line "fewer than 100 real labels: the done-when accepts this only when all real pilot INBOX mail of the last 30 days is labeled (user decision 2026-11-04)".
      2. Both kinds: go/no-go table (category, threshold, precision, recall, kept, decision; the decision text is `go`, `no-go` or `no-go: too few`); metrics per category (precision, recall, support); confusion matrix; sweep table per category; confidence histogram per category (bucket, total, correct); one line "rule results (blocklist, no LLM call): N, right R, wrong W; not in the LLM metrics"; error count with the codes from `errorCodes`.
      3. Only `cases`: whitelist result; injection result with failed ids; one line "blocked by Google (llm_blocked): N (ids), counted as predicted unsure"; usage (avg tokens in/out, latency p50/p95, cost per mail, cost per mailbox per month at 200 mails per day, price source URL and date per model).
         Use an exhaustive `switch` on `report.kind`.
    - Note under the go/no-go table: "minimum support: N kept rows per category (user 2026-11-04)". With the synthetic set (≥ 15 cases per category) every category shows `no-go: too few` under the default 30; the synthetic table is provisional, and the sweep table still shows the precision per threshold.
    - `evalExitCode` rules by `report.kind`: `real` → always 0 (no LLM call, no structural check; the CLI exits 1 only on an error). `cases` → 1 when the whitelist check is below 100% (`passed < total`), an injection case fails (`failedIds` not empty), or `errors` is more than 10% of the cases (`errors / cases.length > 0.1`); else 0. Blocked cases are not errors.
    - CLI: load the config with `loadConfig()` (the Mac `.env` has all keys). Read the case files from `evals/cases/` (repo root), parse them with `evalCaseSchema`. An `LlmConfigError` → print \`LLM config error ${error.code}\` through `log.error` and exit 1 (never the error message). Print the report to stdout through a small helper `out(text)` = `process.stdout.write(\`${text}\n\`)`and, with`--out`, also write the file. Never print case bodies.
  - Test (`eval-report.test.ts`, a hand-made `CasesEvalReport` and a hand-made `RealEvalReport`): for both kinds, the Markdown has a go/no-go row for each of the 5 categories with the right decision text, including `no-go: too few`, and the histogram and the rule line are there; the `cases` header names model, prompt version, bar and minimum support, and the blocked line lists the blocked ids; the `real` Markdown has "N labeled real mails", the under-100 line when `labeled` is 99 and not when it is 100, and no whitelist, injection or usage part; `evalExitCode` rules (`cases`: whitelist 9 of 10 → 1; one failed injection → 1; errors 11% → 1; 2 blocked cases and no errors → 0; clean → 0; `real` → 0); the Markdown has no case body (a body marker in the input cases never appears).
  - Check: `bun run lint && bun run typecheck && bun run test:unit`. A config-error run that uses no quota (review finding 3): `GEMINI_API_KEY=invalid bun run eval --set injection --limit 1`; it must exit 1 and print `LLM config error <code>` (expected `http_400_key`; any `LlmConfigError` code passes) [not verified: that a command-line env value wins over `.env` in Bun; the step 29.1 seed command relies on the same]. Then one live smoke run (free tier, synthetic data, 3 requests of the shared daily quota): `bun run eval --set injection --limit 3 --model gemini-3.5-flash-lite`; write the output summary (no case text) in the step report.
  - Done when: the tests pass, the invalid-key run exits 1 with `LLM config error`, and the smoke run prints a report.
  - Out of scope: real labels from the DB (stage 28), the subset and resume (stage 30), CI runs of the eval (architecture §9 needs a paid key).
