## Stage 4 — IMAP adapter writes (MOVE and COPY paths) on GreenMail [risky]

Checkpoint 1 result (Interia, 2026-11-07): delimiter `/`, namespace prefix `""`; MOVE no, UIDPLUS yes; `UID EXPUNGE` removes only the given UID (`otherDeletedKept` true); a nested CREATE needs the parent first (see `ensureFolder`).

- [x] **4.1 `ImapMailProvider`: folders, folder reads, flags, move, delete**
  - Goal: the IMAP adapter implements the stage 3 port on a server with MOVE (GreenMail) and on one without MOVE but with UIDPLUS (Interia), and the GreenMail contract suite passes on both paths.
  - Files: change `apps/server/src/modules/mail/imap/client.ts`, `apps/server/src/modules/mail/imap/mapper.ts` (`toFolderMessageMeta` adds `flags` from `msg.flags`), `apps/server/src/modules/mail/imap/client.test.ts`, `apps/server/test/integration/imap-contract.test.ts`.
  - Interfaces: `ImapConnectOptions` gets `forceCopyMove?: boolean` (default false; true = ignore the MOVE capability and use the COPY path: for the GreenMail test of the Interia path). `openImapProvider(opts)` passes it to the adapter. Export `createImapMailProvider(client: ImapFlow, opts: { bodyLimitBytes: number; forceCopyMove: boolean }): MailProvider` from `imap/client.ts` (not from `mail/index.ts`), so the unit test can pass a stub client; `openImapProvider` uses it.
  - Decisions:
    - imapflow traps (1.7.8, `lib/commands/move.js`, `expunge.js`; task file "Facts checked"): (a) without MOVE, `messageMove` falls back to `messageCopy` + `messageDelete` and runs the delete also when the COPY returned `false` (mail loss); (b) `messageCopy`, `messageMove`, `messageFlagsAdd`, `messageFlagsRemove` and `messageDelete` catch server errors and return `false`, they do not throw; `messageDelete` also returns `false` when the `UID EXPUNGE` fails after it set `\Deleted`. Rules: call `messageMove` only when the live `client.capabilities.has("MOVE")` is true and `forceCopyMove` is false; never use its fallback. The COPY path and `deleteMessage` check the live `client.capabilities.has("UIDPLUS")`, not the stored capabilities. Every `false` is a `HardError` with its own message: `copy refused`, `move refused`, `flag store refused`, `expunge refused`. `messageDelete` sets `\Deleted` itself: never call `messageFlagsAdd(["\\Deleted"])` before it.
    - `ensureFolder(name)`: `list()`; a folder whose `path` equals `name`, or whose path parts (split on its `delimiter`, after the personal namespace prefix `client.namespace.prefix` is removed) equal `name.split("/")`, is the match → return its `path`. Else create the missing levels parent first: for each prefix of `name.split("/")` that `list()` does not have (found with `matchFolder`, the prefix and delimiter rules above), `mailboxCreate(<prefix parts>)` (checkpoint 1: Interia refuses `mailboxCreate(["AI", "X"])` with `NO [ALERT]` while `AI` is missing, and accepts it after `mailboxCreate("AI")`). Then `list()` again and return the path of the new entry (the server's spelling with its delimiter). Not found after the create → `HardError("folder create failed")`. Any Soft/Hard mapping goes through `guard`.
    - `fetchMetaIn(folder, uid)`: `getMailboxLock(folder)` (the S1a pattern of `findByMessageId`: a missing folder gives null, another SELECT error throws); `fetchOne(String(uid), { …META_QUERY, flags: true }, { uid: true })`; false → null; else `toFolderMessageMeta`. Trap: imapflow `fetchOne` with a UID that is not in the folder returns `false`; a UID above the highest can make some servers return the highest message (the `*` rule applies to ranges only; a single UID is safe). Keep the result only when `msg.uid === uid`.
    - `searchSinceIn(folder, since)`: lock; `search({ since }, { uid: true })`; `false` → `[]`; missing folder → `[]`. `fetchByUidsIn(folder, uids)`: lock; `[]` for an empty list; `fetch(uids.join(","), { …META_QUERY, flags: true }, { uid: true })`; keep only metas whose `uid` is in the asked set; ascending.
    - `setFlags(folder, uid, change)`: lock; `fetchOne` first (false → `MailNotFoundError`); `messageFlagsAdd(String(uid), add, { uid: true })` when `add` is not empty; `messageFlagsRemove` likewise. A `false` return from imapflow is a `HardError("flag store refused")`.
    - `moveMessage(from, uid, to)`: lock `from`; `fetchOne` first (false → `MailNotFoundError`). Live MOVE and not `forceCopyMove`: `messageMove(String(uid), to, { uid: true })`; `false` → `HardError("move refused")`; `newUid` = `uidMap?.get(uid) ?? null`. Else the own COPY path: no live UIDPLUS → `HardError("no UIDPLUS")` before any write (the policy makes such moves `log only`, so this is a guard, not a path); `messageCopy(String(uid), to, { uid: true })`; `false` → `HardError("copy refused")` and stop (no delete); `newUid` from `uidMap`; then `messageDelete(String(uid), { uid: true })` (it sets `\Deleted` and sends UID EXPUNGE); `false` → `HardError("expunge refused")` (the source may now carry `\Deleted`: `locateMessage` skips such a copy, and the next ensure finds the mail in the target). Order matters for the crash cases of stage 9: COPY first, EXPUNGE last; a crash after the COPY leaves two copies, which D5 cleans up.
    - `deleteMessage(folder, uid)`: no live UIDPLUS → `HardError("no UIDPLUS")`; lock; `fetchOne` false → return false; `messageDelete(String(uid), { uid: true })` (no `messageFlagsAdd` before it); `false` → `HardError("expunge refused")`; else true. Never a plain `EXPUNGE`.
    - `findByMessageId` stays in this stage (stage 5 removes it with its callers).
    - Errors keep the S1a mapping (`toMailError`): connection codes → `SoftError`; `authenticationFailed` → `MailAuthError`; else `HardError` with the imapflow `code` when there is one. The `message` of a mapped error never holds a folder path from mail data (the folder names are ours).
  - Test:
    - `client.test.ts` (unit, no server): `imapFlowOptions` unchanged; a stub-client case: `ensureFolder("AI/Spam")` with no `AI` creates `AI` before `AI/Spam` (checkpoint 1); a small test of the folder matcher (`matchFolder(entries, name, prefix)` as an exported pure helper: path equal, parts equal with `.` delimiter, parts equal after a prefix `INBOX.`, none). A stub `ImapFlow` object (only the methods the adapter calls, `capabilities` as a `Map`) checks the `false` rules: `messageDelete` returns `false` → `deleteMessage` throws `HardError` with message `expunge refused`; `messageCopy` returns `false` on the COPY path → `HardError` `copy refused` and `messageDelete` is never called; live capabilities without MOVE → `messageMove` is never called; `messageFlagsAdd` is never called with `\Deleted`.
    - `imap-contract.test.ts`: run `describeMailProviderContract` twice: `"imap-greenmail"` (as today) and `"imap-greenmail-copy-path"` with `forceCopyMove: true`. Both must pass all stage 3 cases. Extra cases on GreenMail: (1) after `moveMessage` on the COPY path, the source folder has no `\\Deleted` leftovers (`search({ deleted: true })` in INBOX is empty); (2) `ensureFolder("AI/Info")` then `serverInfo().folders` lists a path that ends with `Info` (GreenMail delimiter `.` [not verified: the test accepts `AI/Info` or `AI.Info`] and `ensureFolder` returns that path); (3) `moveMessage` with `forceCopyMove` on a server without UIDPLUS is not testable here (GreenMail has UIDPLUS): the fake covers it.
