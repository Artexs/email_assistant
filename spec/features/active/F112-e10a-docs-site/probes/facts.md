# F112 probe facts

Evidence record of the plan (2026-11-15, plan base `116efb17`). `plan.md` cites these facts by number. The probe ran in `.probe-f112/` inside the planning worktree (deleted after): a minimal Starlight site with `npm install`, built with `npx astro build`, served by a Bun static server under the base `/email_assistant`, and opened in the system Chromium through `playwright-core` 1.65.0.

- **F1 Versions** (`npm view`, 2026-11-15): `@astrojs/starlight` 0.43.1 is the newest; peers `astro ^7.2.10` and `@astrojs/markdown-remark ^7.3.0`; it depends on `pagefind ^1.5.2`, `@astrojs/mdx ^8.0.3`, `@astrojs/sitemap ^3.7.4`, `astro-expressive-code ^0.44.0`. `astro` 7.4.12 is the newest (the panel pins it, F101).
- **F2 Build**: Starlight 0.43.1 on Astro 7.4.12 with `site`, `base: "/email_assistant"`, locales `root` (en) and `pl`, and `security.csp` builds 5 pages in about 1 s and a Pagefind index. Config: [astro.config.mjs.txt](astro.config.mjs.txt).
- **F3 CSP gaps**: Astro's `security.csp` hashes only the module scripts. 6 of the 10 inline scripts of a Starlight page (theme, search dialog, sidebar state; Starlight `is:inline` scripts) have no hash in `script-src` ([inline-hashes.out.txt](inline-hashes.out.txt), script [inline-hashes.ts.txt](inline-hashes.ts.txt)). The page also has `style="…"` attributes, which a hashed `style-src` blocks. In Chromium: 4 `script-src-elem` and about 30 `style-src-attr` violations per page. `frame-ancestors` in a meta tag is ignored (console error).
- **F4 Fix**: a post-build pass that adds the sha256 of every inline script to `script-src`, sets `style-src 'self' 'unsafe-inline'` and drops `frame-ancestors` ([csp-finalize.ts.txt](csp-finalize.ts.txt)) gives 0 CSP violations on `/` and `/pl/start/`. Search (Pagefind) returns a result under this CSP without `'wasm-unsafe-eval'` (Chromium only). Check script: [browser-check.mjs.txt](browser-check.mjs.txt).
- **F5 Public output**: the built pages have no `<form>`, no `document.cookie` in `_astro/` or `pagefind/`, and no external `src` or `href` except the canonical and `hreflang` links to the `site` origin.
- **F6 In-place pages**: a loader that runs `docsLoader().load(ctx)` and then adds an entry with `ctx.parseData`, `ctx.renderMarkdown` and `filePath` renders a Markdown file from outside `src/content/docs` as a Starlight page ([in-place-loader.ts.txt](in-place-loader.ts.txt)). Without `filePath` the build fails (`Cannot read properties of undefined (reading 'replace')`). Relative links such as `../docs/architecture.md` stay unchanged in the output (broken on the site).
- **F7 Fallback**: with only `start.md` translated, Starlight builds `/pl/index.html` from the English page (fallback, decision 6).
- **F8 Operator source**: `deploy/README.md` (736 lines) writes hosts as `<machine>.<tailnet>.ts.net` and has the address examples `p@x.test`, `a@b.com.pl` and `a@b.com` (§ around line 621), and the addresses `127.0.0.1`, `172.30.0.1`, `0.0.0.0` (line 263) and `100.100.100.100` (line 148, Tailscale's fixed DNS address, inside `100.64.0.0/10`; review 1 N4).
- **F9 e2e seed**: `apps/server/src/scripts/e2e-seed.ts` writes synthetic addresses on `x.test`.
- **F10 Flags**: `packages/core/src/features.ts`: "Every new behaviour that a user can see ships behind a flag listed here: default off, owner epic, remove-by date." Every flag in the registry defaults off at the plan base.
- **F11 Image**: `deploy/Dockerfile` copies each workspace `package.json` before `bun install`, then the sources of `apps/server`, `apps/web`, `packages/core`. It does not copy `CHANGELOG.md`.
- **F12 Missing sources**: no `CHANGELOG.md`, no OpenAPI file in the repo (ADR 0023 serves `/api/openapi.json` behind login, from F102), no git tag. F102 (E4-A) and F114 (E8b) have no `stages/`.
