## Goal

The owner changes the mailbox mode, the tool switches, the category `auto` flags behind the go/no-go gate and the synced folders, the digest times, the signature (the "style text") and the organization timezone from the web, manages the whitelist, blocklist and VIP rules, and changes the password. ### Facts checked (2026-11-11, sources)

1. **Change password and sessions** (Better Auth 1.7.18, `node_modules/better-auth/dist/api/routes/update-user.mjs`, `changePassword`): body `{ newPassword, currentPassword, revokeOtherSessions? }`; length checks first (`PASSWORD_TOO_SHORT`, `PASSWORD_TOO_LONG`, 400), then a wrong current password gives 400 `INVALID_PASSWORD`; with `revokeOtherSessions: true` it deletes **all** sessions of the user, updates the hash, creates a new session and sets its cookie in one transaction; without it no session changes. The S5a hook writes `web.password_changed` (`platform/auth.ts:163-176`); `session.create.after` writes `web.login` only for `/sign-in/email`, so the new session writes no login row. `POST /revoke-sessions` deletes every session of the user, also the current one, and returns `{ status: true }` (`api/routes/session.mjs:420-449`); `/revoke-other-sessions` keeps the current one (`:450-479`). Both use `sensitiveSessionMiddleware` (a valid session, read from the database; `:304-311`). The React client derives its methods from the paths (`authClient.changePassword`, `authClient.revokeSessions`); results are `{ data, error }` objects (`LoginPage.tsx`).
