## Goal

The server authenticates a web user with Better Auth, serves the static Astro build from the same origin, guards every page and API route with the session and the tenant context, and the owner can set a first password through a CLI link and log in. Playwright and CI are ready for the next segments.

## Done when

- `bun run web:invite --org-id … --user-id …` prints a one-time link; the setup page sets a password; `/login` signs the owner in; `/api/me` returns the user, the organization, the role, the scopes and `mailboxesInAuthError`; sign-out ends the session (integration tests and the Playwright smoke test in the `mobile` and `desktop` projects).
- Without a session: `/api/*` answers 401 JSON; a page path redirects to `/login?next=…`; `/login`, `/setup`, `/_astro/*`, `/health`, `/api/auth/*` stay public. `requireOwner` answers 403 `owner_only` for an assistant and `requireTenant` 403 `no_organization` for a user without a membership (unit tests; S5a has no owner route yet); the route matrix covers 401, 403 `bad_origin`, 404 JSON for an unknown API path, 400 `details` without the input and 413 (the 404 for another organization's id arrives with the first id route, S5b).
- Public sign-up is off; only the D1 allow-list of `/api/auth/*` paths reaches Better Auth (`request-password-reset`, `update-user`, `sign-in/social` and the rest answer 404 over HTTP); the reset token is single-use; a reset ends the other sessions; an owner created with a mixed-case e-mail signs in (the migration lower-cases `users.email`, D2 and D11) (tests).
- The hardening of D5 is on: the header CSP without `script-src` plus the Astro `experimental.csp` meta with the hashes (an app page loads with no CSP console error in Playwright), frame denial, origin check on non-safe `/api/*` methods (403 `bad_origin`), body limit, `Bun.serve` `idleTimeout` 90 s, HSTS only on `https://` base URLs; the 400 `details` hold path, code and message only (D9); a log test proves that no token, cookie, secret, e-mail address or raw path reaches a log line.
- With `WEB_BASE_URL` empty the server starts as today and logs `web is off (WEB_BASE_URL is empty)`; the existing unit, integration and CLI tests stay green.
- `bun run web:build` produces `apps/web/dist` with the shell (U2, U3: bottom tabs under 1024 px, sidebar above), `/login`, `/setup`, `/404` and placeholder app pages; every string comes from `apps/web/src/i18n/en.ts` (the ESLint rule `react/jsx-no-literals` guards the islands and the shell and auth components).

### Facts checked (2026-11-08, this session; scripts and full results: `notes/2026-11-08-s5a-probes/README.md`)

1. **Bun 1.3.14 = Bun 1.4.4 for Better Auth 1.7.18:** the same 19 checks pass in `oven/bun:1.3.14` (`--network host` against the probe database `email_assistant_s5aprobe`) and on this PC; `Bun.serve({ idleTimeout: 90 })`, `Bun.password.hash` and `node:net` `BlockList` exist on both.

3. **E-mail case:** the D11 CHECK `email = lower(email)` refuses a mixed-case insert (`23514`); `requestPasswordReset` and `signInEmail` with an upper-case e-mail find the lower-case row (Better Auth lower-cases the lookup). So the service lower-cases on insert (D2) and the API accepts any case.
4. **Reset flow:** the URL is `<WEB_BASE_URL>/api/auth/reset-password/<token>?callbackURL=<redirectTo>` (120 characters); the first `resetPassword` creates the `credential` account (scrypt hash in `auth_accounts.password`); the token is single-use (`INVALID_TOKEN`); a later reset revokes every session (`revokeSessionsOnPasswordReset: true` → 0 rows); the used verification row is deleted; `GET /reset-password/:token` redirects to `callbackURL?token=` or `callbackURL?error=INVALID_TOKEN` (source `api/routes/password.mjs`).
5. **Audit hooks (changes D4):** `emailAndPassword.onPasswordReset({ user })` fires on the first and on every later reset with `user.id`; `account.update.after` gets a **number** on `/reset-password` (the `updateMany` count) but the **full account** (`userId`, `providerId`) on `/change-password`, with `ctx.path` and `ctx.context.session.user.id`; `session.create.after` fires on `/sign-in/email` **and on `/change-password`** (the session is re-created), with `ctx.path` telling them apart.
6. **Cookie:** `ea.session_token` (`cookiePrefix: "ea"`), `Max-Age=2592000; Path=/; HttpOnly; SameSite=Lax`, no `Secure` on `http://`; on `https://` Better Auth adds `Secure` and the `__Secure-` name prefix (`cookies/index.mjs`).
7. **Sign-up and errors:** `disableSignUp: true` refuses the server-side `signUpEmail` (`EMAIL_PASSWORD_SIGN_UP_DISABLED`); a wrong password and an unknown e-mail give the same `INVALID_EMAIL_OR_PASSWORD`; `changePassword` with `revokeOtherSessions: true` keeps 1 of 2 sessions.
8. **Client IP (changes D1, D5):** Better Auth reads the IP only from request headers (`@better-auth/core/dist/utils/ip.mjs` `getIP`: `advanced.ipAddress.ipAddressHeaders`, default `x-forwarded-for`; with `trustedProxies` the chain is stripped from the right; without, a single-value header is trusted; the TCP peer is never seen). Without an IP the limiter uses one shared bucket per path and logs one `warn`. `rateLimit.customRules["/sign-in/email"] = { window: 10, max: 3 }` gives 429 on the 4th wrong sign-in.
9. **Static serving (D6):** `@hono/bun` `serveStatic({ root })` with an absolute root serves `mailboxes/index.html` for `/mailboxes` and `/mailboxes/`, `onFound(path, c)` sets `Cache-Control` per path, a miss falls to `app.notFound` (the `404.html` body with 404), `..` never reaches a file, `HEAD` works.
10. **Origin checks (D5):** the own check answers 403 `bad_origin` first for a missing or foreign `Origin`; a good `Origin` (`WEB_BASE_URL` or `http://localhost:4321`) passes both and Better Auth answers 401 for a wrong password (no double 403); Better Auth refuses a non-GET **without** `Origin` (`MISSING_OR_NULL_ORIGIN`) even with `Sec-Fetch-Site: same-origin` (a browser always sends `Origin` on a POST). Hono's `csrf()` is not used.

### S5a design decisions (main session, 2026-11-08; why in each line)

- **W1 Client address.** `platform/http.ts` exports the pure `clientAddress(peer: string | undefined, forwardedFor: string | undefined, trusted: BlockList): string | null`: strip an IPv4-mapped prefix (`::ffff:a.b.c.d` → `a.b.c.d`); when the peer is in `trusted` and `x-forwarded-for` exists, walk the comma list from the right and return the first entry not in `trusted`; an entry that is not a plain IP (for example `203.0.113.9:5123`) ends the walk and returns the peer (fail closed: the entries left of it are client-controlled; second cold review, finding 5); else return the peer. `WEB_TRUSTED_PROXIES` builds the `BlockList` once (`addSubnet` for `a.b.c.d/n`, `addAddress` otherwise; IPv6 the same with `ipv6`). The `/api/auth/*` handler builds `new Request(url, { method, headers, body, duplex: "half" })` whose headers are the incoming ones minus `x-client-ip` plus `x-client-ip: <address>` when one is known; Better Auth gets `ipAddressHeaders: ["x-client-ip"]`. Peer source: `getConnInfo(c).remote.address` from `@hono/bun`, injectable as `web.connInfo` for tests (the route tests pass `() => "203.0.113.9"`). Why: fact 8 (the library never sees the peer; a direct client could spoof `x-forwarded-for` otherwise); the rate limit and `auth_sessions.ip_address` then hold the real client.
- **W2 Audit hooks (D4 as refined).** `web.login` ← `databaseHooks.session.create.after(session, ctx)` when `ctx?.path === "/sign-in/email"`; `web.password_set` ← `emailAndPassword.onPasswordReset({ user })`; `web.password_changed` ← `databaseHooks.account.update.after(account, ctx)` when `ctx?.path === "/change-password"` and `account.providerId === "credential"` (actor `account.userId`).
