## Stage 24 — Cost gates: 7-day rule with the backfill waiver, daily cap [risky]

- [ ] **24.1 `too_old` skip, daily cap per Los Angeles day**
  - Goal: the worker skips mail older than 7 days unless the backfill stored it, and stops LLM calls of a mailbox at the daily cap.
  - Files: create `packages/core/src/triage/quota-day.ts`, `packages/core/src/triage/quota-day.test.ts` (export from the triage index); change `apps/server/src/modules/triage/service.ts`, `apps/server/src/modules/triage/jobs.ts`; extend `apps/server/test/integration/triage-service.test.ts` and `triage-job.test.ts`.
  - Interfaces:
    - `QUOTA_TIMEZONE = "America/Los_Angeles"`; `quotaDayStart(now: Date, timeZone: string): Date`; `nextQuotaDayStart(now: Date, timeZone: string): Date`.
    - `TriageDeps` gets `dailyCap: number`. `TriageOutcome` gets `{ kind: "skipped" }` and `{ kind: "capped"; until: Date; dayStart: Date }`. `TriageJobDeps` gets `dailyCap: number` and passes it on.
  - Decisions:
    - 7-day rule (architecture §4.1 rule 8, ADR 0012), the first check in `triageOne`, before the hard rules: `email.received_at < now − 7 days` and `email.backfilled_at === null` → one transaction: `finishEmail(…, { status: "skipped", skipReason: "too_old" })` (`false` → `{ kind: "lost" }`) + audit `email.skipped` (reason code `too_old`, `data` `{ mailbox_id }`). No LLM call. Return `{ kind: "skipped" }`. A mail with `backfilled_at` set skips this rule (user decision 2026-11-04: the waiver is only for mail that the one-off backfill stores or re-queues, stages 31–33); every other mail keeps the 7-day rule.
    - Daily cap (ADR 0012; main-session decisions 2026-11-04, review findings 3 and 14): right before the LLM call (after the hard rules, so blocklist and too-old mails need no call and pass at the cap): `dayStart = quotaDayStart(now, QUOTA_TIMEZONE)`; `countLlmCallsSince(db, ctx, mailbox.id, dayStart) >= deps.dailyCap` → `until = nextQuotaDayStart(now, QUOTA_TIMEZONE)`; `releaseEmail(…, { nextAttemptAt: until, countAttempt: false })`; return `{ kind: "capped", until, dayStart }`. The cap counts every call attempt (`llm.call` rows, step 20.1), per Los Angeles day while on the free tier, because the free-tier daily quota resets at midnight Pacific time [not verified]. The billing task (`tasks/planned/gemini-billing-budget-alert.md`) checks the day rule again.
    - Job: on `capped` continue with the next claimed mail of the batch (each mail checks the cap; mails that need a call go to the next quota day one by one; blocklist and too-old mails still finish). Log one `warn` per mailbox per quota day (a `Map<mailboxId, dayStart ISO>` in the job): \`daily LLM cap reached for mailbox ${mailboxId}: ${cap} calls since ${dayStart ISO} (America/Los_Angeles day); mail waits until ${until ISO}\`. The test checks this line (no test hook, review finding 23).
    - `quotaDayStart`: read the local date in the time zone with `Intl.DateTimeFormat("en-US", { timeZone, year: "numeric", month: "2-digit", day: "2-digit", hour: "2-digit", minute: "2-digit", second: "2-digit", hourCycle: "h23" }).formatToParts(now)`; compute the zone offset as (local parts read as UTC) − `now`; candidate = `Date.UTC(y, m − 1, d)` − offset; read the offset again at the candidate time and correct once (daylight-saving change days). `nextQuotaDayStart` = `quotaDayStart` of (`quotaDayStart(now)` + 26 h). `QUOTA_TIMEZONE` is a code constant, not a config key: a change of the quota day is a code change (commit). Bun's time-zone list has gaps (`notes/2026-11-03-bun-timezones.md`); the test proves that `America/Los_Angeles` works.
    - The Cloud Billing budget alert is not in S1b (`tasks/planned/gemini-billing-budget-alert.md`). The in-app part is the cap and its `warn` line (S2 adds a Telegram notice).
  - Test:
    - `quota-day.test.ts`: 2026-11-04T07:59Z → start 2026-11-03T08:00Z, next 2026-11-04T08:00Z (PST); 2026-11-04T08:00Z → start 2026-11-04T08:00Z; 2026-11-01T12:00Z (the day daylight saving time ends) → start 2026-11-01T07:00Z, next 2026-11-02T08:00Z; 2027-03-14T12:00Z (the day it starts) → start 2027-03-14T08:00Z, next 2027-03-15T07:00Z.
    - `triage-service.test.ts`: an 8-day-old mail → `skipped` / `too_old`, an `email.skipped` audit row, no LLM call; an 8-day-old mail with `backfilled_at` set → triaged with an LLM call; cap 2 with 2 `llm.call` rows since the quota day start → `{ kind: "capped" }`, the mail `pending` with `next_attempt_at` = the next quota day start, no LLM call; 2 `llm.call` rows from before the quota day start do not count; a blocklist mail is still triaged at the cap.
    - `triage-job.test.ts` (`pauseOtherMailboxes` first): at the cap, two runs give one `warn` line `daily LLM cap reached for mailbox …`; a blocklist mail in the same batch is triaged.
