      - Decision: (1) The temporary pilot Interia mailbox counts as test mail. Its real mail may go to the Gemini API free tier. Quote the user: "A mail is just a real one but temporary, it just contains some emails but there is nothing important, we can treat it like test email, and we will use Gemini free tier for now." (2) This is for this one mailbox only. Cloud Billing (Gemini API paid tier), or Vertex AI as in ADR 0012, stays required before the mail of any other person, and before a mailbox of the user that is not temporary. (3) `TRIAGE_LLM_SCOPE` (`off` | `synthetic` | `all`, default `off`) is the safety switch. With `all`, the worker triages only the mailbox whose address equals `TEST_MAILBOX_ADDRESS`, until a paid-tier key exists. `synthetic` is not a security boundary: it picks mail by the Message-ID suffix `@ea-seed.test>`, and any sender can write such a Message-ID; use `synthetic` only on a test mailbox. (4) The Cloud Billing budget alert waits until billing is on (`tasks/planned/gemini-billing-budget-alert.md`). The in-app daily cap `LLM_DAILY_CAP` (default 300) stays. (5) Start value of the classifier model: `gemini-3.5-flash-lite`. The S1b eval result goes to `docs/architecture.md` §6.3 and the S1b task file, not into this ADR. (6) Simple LLM calls (user, 2026-11-04: "just make a call to the LLM and don't complicate it with additional parameters like temperature"): `platform/llm.ts` sends only the model, the system instruction, the prompt, the JSON response type and schema, and the abort signal; no temperature, no thinking setting. Each model uses its default thinking. `gemini-3.5-flash-lite` defaults to "minimal" (https://ai.google.dev/gemini-api/docs/thinking, read 2026-11-04), so the default classifier meets the ADR 0012 rule "`classify` uses the lowest thinking setting". `gemini-3.8-flash` (comparison only) uses its default ("medium"). ADR 0012 stays unchanged.
