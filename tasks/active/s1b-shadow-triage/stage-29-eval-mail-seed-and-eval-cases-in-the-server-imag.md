## Stage 29 — Eval mail seed and eval cases in the server image [risky]

- [ ] **29.1 `mailbox:seed --eval-cases`, RFC 2047 headers, eval cases in the server image**
  - Goal: put a fixed subset of the synthetic eval cases into the test mailbox INBOX, so the whole pipeline runs on synthetic mail, also on the VPS.
  - Why [risky]: this is the only S1b code path that writes into a mailbox (IMAP APPEND into the INBOX of the test mailbox, behind the `TEST_MAILBOX_ADDRESS` guard), and it changes the server image (`deploy/Dockerfile`).
  - Files: change `apps/server/src/modules/mail/seed.ts` (RFC 2047 encoding), `apps/server/src/modules/mail/seed.test.ts`, `apps/server/src/modules/mail/tools.ts` (`seedMailbox` takes optional messages), `apps/server/src/scripts/mailbox-seed.ts` (`--eval-cases synthetic|injection|all`, `--per-category n`), `deploy/Dockerfile` (add `COPY evals/cases evals/cases`).
  - Interfaces: `seedMailbox(deps, ctx, mailboxId, opts: { count: number; testAddress: string | undefined; messages?: SeedMessage[] })` (with `messages`, `count` is ignored and each message is appended once).
  - Decisions:
    - The `TEST_MAILBOX_ADDRESS` guard stays unchanged (the pilot address is also the test address: user decision 2026-11-04, one mailbox).
    - The script reads the case files from `evals/cases/` (repo root, also `/app/evals/cases` in the image), parses them with `evalCaseSchema` and picks the cases with `selectCases(cases, { perCategory })` (step 12.1): `--eval-cases synthetic --per-category 4` = 20 mails.
    - Each case becomes a `SeedMessage`: Message-ID `<eval-${caseId}-${randomUUID()}@ea-seed.test>` (synthetic by the gate rule), `From` = the case `from` (display name and address split with `splitAddress`, step 12.1: the same rule as the eval runner, review finding 5), `To` = the mailbox address, `Date` = now, header `X-EA-Seed: 1`, text body from the case. Sender rules of the cases are not copied to the DB: the user adds them with `rules:add` when needed.
    - RFC 2047 (review finding 19): encode as `=?UTF-8?B?…?=` only the `Subject` value and the display name of an address (`Name <addr>` → encoded name, raw `<addr>`). Never encode the address itself: an encoded From address gives `from_address` NULL after the sync. A non-ASCII address part, or a non-ASCII value in any other header, still throws. A line break in any header still throws.
    - Docker: `.dockerignore` excludes `tasks`, `notes`, `docs`, `.ai`, not `evals`; keep it so. Copy only `evals/cases` (not `evals/.runs`, not `evals/results`). `eval --real` must not need the files (step 28.1).
  - Test (`seed.test.ts`): a Polish subject renders as an encoded word and `mailparser` reads back the same subject (as in `imap/mapper.test.ts`); `From: Łukasz Nowak <lukasz@firma.test>` renders an encoded name and a raw address, and `mailparser` reads back the address `lukasz@firma.test` and the name; a non-ASCII address part throws; a header with a line break still throws; the existing seed tests pass.
  - Check: `bun run lint && bun run typecheck && bun run test:unit && bun run test:int`. Image: `docker build -f deploy/Dockerfile -t ea-server-s1b-check . && docker run --rm ea-server-s1b-check ls evals/cases` shows `injection.json` and `synthetic.json`; then `docker image rm ea-server-s1b-check`. Manual on GreenMail (`bun run dev:up`; the Mac `.env` has an empty `TEST_MAILBOX_ADDRESS`, so set it on the command line): `TEST_MAILBOX_ADDRESS=<GreenMail mailbox address> bun run mailbox:seed --org-id … --mailbox-id … --eval-cases synthetic --per-category 1`. Then run a sync (review finding 22): start the server with `bun run start` (without `TRIAGE_LLM_SCOPE`, so the triage worker is off and no LLM call happens), wait for the log line `synced <mailbox id>` (the sync job runs every 5 minutes, so this can take up to 5 minutes), then stop the server with Ctrl-C. Check: `docker compose -f deploy/compose.yaml -f deploy/compose.dev.yaml --env-file .env exec -T db psql -U postgres -d email_assistant -c "SELECT count(*) FILTER (WHERE from_address IS NOT NULL) AS with_from, count(*) AS total FROM emails WHERE mailbox_id = '<mailbox id>' AND message_id_header ILIKE '<eval-%@ea-seed.test>';"` gives `with_from` 5 and `total` 5.
  - Done when: the tests pass, the image has the case files, and the manual seed works on GreenMail.
  - Out of scope: seeding the pilot mailbox (step 37.1).
