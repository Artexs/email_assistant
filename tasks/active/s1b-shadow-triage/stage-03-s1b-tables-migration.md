## Stage 3 — S1b tables migration [risky]

- [x] **3.1 Migration for sender rules, triage results, feedback, actions, audit log and `emails.backfilled_at`**
  - Goal: the S1b tables exist with org filters, checks and an append-only audit log; `emails` can mark backfilled mail.
  - Files: create `db/migrations/20261104000001_triage.sql`; regenerate `apps/server/src/platform/db/schema.ts` with `bun run db:types` (never edit it by hand); create `apps/server/test/integration/triage-schema.test.ts`.
  - Interfaces (SQL, `-- migrate:up` / `-- migrate:down`):
    - `ALTER TABLE emails ADD CONSTRAINT emails_id_org_key UNIQUE (id, org_id);` (needed for the composite foreign keys below).
    - `ALTER TABLE emails ADD COLUMN backfilled_at timestamptz;` (NULL = stored by the normal sync; set only by the one-off backfill, stages 31–33; the worker's 7-day rule does not apply to rows with a value, user decision 2026-11-04).
    - `sender_rules`: `id uuid PK default gen_random_uuid()`, `org_id uuid NOT NULL REFERENCES organizations (id) ON DELETE CASCADE`, `mailbox_id uuid NULL`, `pattern text NOT NULL CHECK (length(pattern) > 0 AND pattern = lower(pattern))`, `kind text NOT NULL CHECK (kind IN ('whitelist','blocklist','vip'))`, `created_at timestamptz NOT NULL DEFAULT now()`, `FOREIGN KEY (mailbox_id, org_id) REFERENCES mailboxes (id, org_id) ON DELETE CASCADE`; `CREATE UNIQUE INDEX sender_rules_key ON sender_rules (org_id, mailbox_id, pattern, kind) NULLS NOT DISTINCT;`.
    - `triage_results`: `id uuid PK`, `org_id uuid NOT NULL`, `email_id uuid NOT NULL`, `category text NOT NULL CHECK (category IN ('urgent','needs_reply','delegation','info','notification','spam','unsure'))`, `vip boolean NOT NULL DEFAULT false`, `confidence real NOT NULL CHECK (confidence BETWEEN 0 AND 1)`, `reason_code text NOT NULL`, `reason text`, `fields jsonb NOT NULL DEFAULT '{}'`, `model text` (NULL = no LLM answer), `prompt_version text`, `tokens_in integer`, `tokens_out integer`, `latency_ms integer`, `created_at timestamptz NOT NULL DEFAULT now()`, `FOREIGN KEY (email_id, org_id) REFERENCES emails (id, org_id) ON DELETE CASCADE`; indexes `(email_id, created_at DESC)` and `(org_id, created_at)`.
    - `triage_feedback`: `id uuid PK`, `org_id`, `email_id`, `verdict text NOT NULL CHECK (verdict IN ('right','wrong'))`, `true_category text NULL CHECK (same list as above)`, `source text NOT NULL CHECK (source IN ('cli','telegram','undo','imap_move','web'))`, `user_id uuid NULL REFERENCES users (id) ON DELETE SET NULL`, `created_at`, FK `(email_id, org_id)` → `emails` `ON DELETE CASCADE`; index `(email_id, created_at DESC)`.
    - `actions`: `id uuid PK`, `org_id`, `email_id`, `type text NOT NULL CHECK (type IN ('move','mark_read','flag','save_summary'))`, `payload jsonb NOT NULL DEFAULT '{}'`, `status text NOT NULL CHECK (status IN ('ready','applying','applied','awaiting_approval','approved','rejected','expired','undone','logged','failed'))`, `status_reason text`, `attempts integer NOT NULL DEFAULT 0`, `next_attempt_at timestamptz`, `locked_at timestamptz`, `last_error text`, `provider_result jsonb`, `idempotency_key text NOT NULL`, `outgoing_message_id text`, `depends_on_action_id uuid` with `FOREIGN KEY (depends_on_action_id, org_id) REFERENCES actions (id, org_id)`, `reverses_action_id uuid` with `FOREIGN KEY (reverses_action_id, org_id) REFERENCES actions (id, org_id)` (composite, reviewer finding: tenant integrity), `notified_at timestamptz`, `approved_by uuid REFERENCES users (id) ON DELETE SET NULL`, `approved_at timestamptz`, `approved_via text`, `created_at`, `updated_at timestamptz NOT NULL DEFAULT now()`, FK `(email_id, org_id)` → `emails` `ON DELETE CASCADE`, `UNIQUE (org_id, idempotency_key)`, `UNIQUE (id, org_id)`; indexes `(status, next_attempt_at)` and `(email_id)`.
    - `audit_log`: `id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY`, `org_id uuid NOT NULL REFERENCES organizations (id) ON DELETE CASCADE`, `email_id uuid NULL`, `action_id uuid NULL`, `actor text NOT NULL` (`system` or a user id), `event text NOT NULL`, `reason_code text`, `data jsonb NOT NULL DEFAULT '{}'`, `created_at timestamptz NOT NULL DEFAULT now()`, FKs `(email_id, org_id)` → `emails` and `(action_id, org_id)` → `actions (id, org_id)`, both `ON DELETE CASCADE`; indexes `(org_id, created_at)` and `(org_id, event, created_at)` (the daily cap counts `llm.call` rows). Then `REVOKE UPDATE, DELETE, TRUNCATE ON audit_log FROM app;`.
    - `-- migrate:down`: drop the five tables in reverse order, then `ALTER TABLE emails DROP COLUMN backfilled_at;` and `ALTER TABLE emails DROP CONSTRAINT emails_id_org_key;`.
  - Decisions: column lists from architecture §5, plus `emails.backfilled_at` (user decision 2026-11-04, answer 3: the 7-day waiver for backfilled mail needs a per-row mark; a column is the smallest safe mechanism: no extra query, no audit lookup, and the normal sync never sets it). `audit_log` is append-only: the role `app` has only INSERT and SELECT on it (code-patterns, modules §3.6). Never edit an applied migration. Column names avoid SQL reserved words. The default privileges from `20261103000001_app_grants.sql` give `app` the rights on the new tables and the identity sequence.
  - Test (`triage-schema.test.ts`, app role, `withRollback`, savepoints for statements that must fail): one row in each table inserts; `UPDATE audit_log` and `DELETE FROM audit_log` fail with `permission denied`; a bad category, status, verdict, source or kind fails the check; a second `sender_rules` row with the same `(org, NULL mailbox, pattern, kind)` fails; an upper-case pattern fails; a `triage_results` row with an `email_id` of another org fails the foreign key; a new `emails` row has `backfilled_at` NULL.
  - Check: `bun run dev:up && bun run db:migrate && bun run db:types && bun run lint && bun run typecheck && bun run test:int`. Also `bun run db:rollback && bun run db:migrate` (down and up both work).
  - Done when: the tests pass and `schema.ts` has the five new tables and `emails.backfilled_at`.
  - Out of scope: repository code, `delegations`/`chat_links`/`digests` tables (later slices).
