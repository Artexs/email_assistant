  (`20261103100001_mail.sql:18`); the default grants cover the new table.
- D4: no cursor path ends at 0 for a folder with mail: initial and rescan set `max(uidNext - 1, highest kept)` with `uidNext ≥ highestUid + 1`; incremental
  only moves up; an empty folder gives 0, which is right. The old `inboxStatus` takes STATUS `UIDNEXT 1` as finite (`client.ts`), so the hidden INBOX case is real.

  `append()` takes no lock; `getMailboxLock` queues per connection with an opt-in `acquireTimeout` only, so the N1 trap is real. The new read methods
  (`folderStatus`, `fetchAbove`, `fetchBodyText`, `listFolders`) hold at most one lock and call no locking method inside it; `transferByAppend` releases
  the lock before `append` and `fetchMetaIn`.
