## Goal

The owner connects, pauses, resumes, re-authorises and removes a mailbox from the web, links and unlinks Telegram, and sees on the onboarding checklist what is still missing. The panel shows honestly which mailboxes the triage, the actions and the sends cover (the env scopes).

4. **The delete graph** (every migration read): `mailbox_credentials`, `mailbox_settings`, `emails`, `sender_rules` (mailbox-scoped), `outbox` (`mailbox_id`), `delegations` (`mailbox_id`), `mailbox_folders` cascade from `mailboxes`; `triage_results`, `triage_feedback`, `actions`, `audit_log` (`email_id`), `outbox` (`email_id`), `delegations` (`email_id`) cascade from `emails`; `audit_log` (`action_id`), `delegations` (`draft_action_id`, `send_action_id`) cascade from `actions`. `actions.depends_on_action_id` and `reverses_action_id` reference `actions` with no action (both ends are rows of the same mail, deleted in the same statement). `delegations.answered_email_id → emails ON DELETE SET NULL` (an answer mail of the removed mailbox to a delegation of another mailbox only loses the link). `delegations.delegate_id → delegates` (no cascade; `delegates` are organization rows and stay). `audit_log` rows with only `data.mailbox_id` (pause, resume, password, mode, policy, switch, sync folders) need the explicit delete.

Tap edits read `outbox.text` only through the dedup keys `approval:…`, `approval_set:…`, `send_result:…`, `delegation_answered:…` (`channels/callbacks.ts:210-220`); those rows hold an `email_id` and go with the cascade, so no tap ever edits a message into "[removed]".
6. **Module edges:** `channels` imports `mail` (`channels/commands.ts:30`), so `mail/remove.ts` cannot import `channels`: the notice comes through an injected hook from the composition root (`web.ts`). `tenancy` must not import `mail`, `channels`, `audit` queries of other modules: the onboarding state is injected like `countMailboxes` (S5a stage 8).

8. **The claim race (D11):** `claimEmails` is one statement (a CTE with `FOR UPDATE SKIP LOCKED` and the `UPDATE`); its row locks end with that statement. So the realistic race is "claim committed → `removeMailbox` → the job's `saveTriage` on a deleted mail"; a lock wait happens only while another transaction is open on the rows.
