- [ ] **19.1 The user tries S4 on the Mac with GreenMail and the dev bot**
  - Goal: the done-when items work end to end on a real phone, a real local IMAP and SMTP server and the real LLM, before anything goes to the VPS.
  - Files: this task file ("Results": the measured facts, no mail data, no chat id, no token; one log line).
  - Interfaces: none (operations). Dev DB shell: `D="docker compose -f deploy/compose.yaml -f deploy/compose.dev.yaml --env-file .env"`; SQL with `$D exec -T db psql -U postgres -d email_assistant -c "<SQL>"`. GreenMail IMAP `127.0.0.1:3143`, SMTP `3025`, auth off (a user exists after its first login or delivery, `notes/2026-11-03-greenmail-facts.md`). The IMAP one-off reads use the `bun -e` imapflow snippet of S3 stage 16 (dev only, never against Interia).
  - Decisions:
    - The main session runs the commands; the user uses the phone and reports what they see. The dev bot token must be in `.env` (S2 stage 21); without it the Telegram steps are replaced by `handleCallback` calls through a one-off `bun -e` against the dev DB, and the stage log says so.
    - Scopes on the command line of this run only: `TRIAGE_LLM_SCOPE=synthetic ACTIONS_SCOPE=synthetic SEND_SCOPE=self SEND_TEST_ADDRESSES=<delegate address>`; nothing in `.env` changes.
    - The delegate for the run: `dev-delegate-<4 hex>@localhost` (a GreenMail user that exists after the first delivery); the "sender" of the clarification case is a `@…test` address outside the list, so its send is held by the scope (that is a test of the gate, step 9).
    - **Every hand-made mail that the run needs triaged gets a synthetic `Message-ID`** (`<…@ea-seed.test>`): `TRIAGE_LLM_SCOPE=synthetic` claims only such mail (`mailKindFilter("synthetic")`, `mail/repo.ts`), so a mail with nodemailer's random id is never triaged and the reply rule never runs (review round 2 N4). In this run that is the reply of step 8; the seeded mails of `mailbox:seed` have such ids already; the APPEND of step 7 is not triaged on purpose (the own-mail skip drops it at sync).
    - The chaser is triggered on demand with `bun run job:run --name delegation.chaser --force` (the flag skips the 07:30 and once-per-day gate, stage 18), so the run can happen at any time of day.
  - Steps:
    1. `bun run dev:up && bun run db:migrate`. The dev org and GreenMail mailbox from the S3 dev run (`select o.id, mb.id, mb.address from organizations o join mailboxes mb on mb.org_id = o.id;`). `bun run mailbox:settings mode --org-id <org> --mailbox-id <mb> --mode assist`, then `switch --name create_draft --value on` → the table shows `create_draft on`. `bun run delegates:add --org-id <org> --name "Dev Delegate" --email dev-delegate-<hex>@localhost --tags oferty,faktury` → an id; `delegates:add … --email <the GreenMail mailbox address>` → `refused`.
    2. Start the server in its own terminal with the scopes above: the log has `sends go only to the SEND_TEST_ADDRESSES list (SEND_SCOPE=self)`, `actions committer applies mailbox changes to synthetic mail only`, `telegram: polling as @<dev bot>`, `actions expiry: hourly`, `delegation chaser: every 15 min`.
    3. Write `t0` (UTC). `TEST_MAILBOX_ADDRESS=<GreenMail address> bun run mailbox:seed --org-id <org> --mailbox-id <mb> --eval-cases delegation --per-category 3` (3 delegation cases: at least one with a clear delegate and one clarification case; the case delegate names do not match "Dev Delegate": the LLM gets the real delegates list of the mailbox, so it picks the only delegate or asks a question — write what it did).
    4. Within 6 minutes: SQL `select a.type, a.status, a.payload->>'kind' as kind, a.depends_on_action_id is not null as dep from actions a join emails e on e.id = a.email_id where e.mailbox_id = '<mb>' and e.created_at > '<t0>' order by e.received_at, a.type;` → for the delegation case: `create_draft` `applied` (`kind delegation`) and `send` `awaiting_approval` with `dep` true; `select status, task_summary is not null, due_at from delegations order by created_at desc limit 3;` → `drafted`. IMAP: the user's GreenMail `Drafts` holds a message with the `X-Ea-Action-ID` header and `Fwd: <subject>` (the `bun -e` listing: `client.fetch("1:*", { envelope: true, headers: ["x-ea-action-id"] })` in `Drafts`).
    5. Phone (within one notifier tick, outside quiet hours): the approval message `📤 Send? Delegation to Dev Delegate <address>`, `From: <case sender> · ⚠️ external sender`, `Subject: Fwd: …`, `Draft:` with the Polish or English template text, `Quoted original:` with the `> ` lines, two buttons. Write the length of the message (`select length(text) from outbox where kind = 'approval' order by created_at desc limit 1;`).
    6. Tap `📤 Send` → toast `⏳ Sending within a minute.`; the message is edited to `… ⏳ Approved HH:MM, sending.` without buttons. Within 30 s SQL: the send `applied` with `provider_result->>'response'` starting `250`, `sent_copy` `appended`, `outgoing_message_id` `<ea-…@localhost>`; the delegation `sent` with `sent_message_id` and `due_at`; a reverse `create_draft` row, `applied` within the next tick, the original draft `undone` / `sent`. IMAP: the user's `Drafts` is empty, `Sent` holds the copy (`\Seen`); the delegate's INBOX (login as `dev-delegate-<hex>@localhost`) holds the mail with the header, `From: <owner display name> <GreenMail address>`, the task text and the quote; write the subject shape and the raw size. Phone: `✅ Sent to Dev Delegate <address> · Fwd: …` (the `send_result` notice).
    7. The own-mail skip: `bun -e` APPENDs the raw of the sent mail (fetched from the delegate's INBOX as `source`) into the **user's** INBOX (Interia would do this by itself for a send to self) → within 6 minutes the server log has the sync line `sync <mailboxId> <mode>: fetched …, skipped own 1, ignored below cursor …` (`mail/sync.ts:413`; grep `skipped own 1`: M26) and no new `emails` row with that `Message-ID`.
    8. Reply → answered: `bun -e` with nodemailer to GreenMail SMTP 3025, `from: <delegate address>`, `to: <user address>`, `inReplyTo: <the sent message id>`, `references: <the sent message id>`, `messageId: "<reply-<8 hex>@ea-seed.test>"` (synthetic, so `TRIAGE_LLM_SCOPE=synthetic` claims it), subject `Re: Fwd: …`, text `Zrobione.` → within 6 minutes: the delegation `answered` with `answered_email_id`, audit `delegation.answered`; the reply triaged (any category); phone: `📩 Dev Delegate answered · …` with `✅ Done` → tap → `✅ Done.`, the delegation `done`.
    9. The scope gate: the clarification case's send (to the case sender) → the approval message `📤 Send? Question to the sender <address>`; tap Send → toast `Approved. Sending is held by SEND_SCOPE on the server; /status shows it.`; `/status` → `Approvals: 0 waiting for your tap · 1 approved, held by SEND_SCOPE=self`, `Send: only to your test addresses (SEND_SCOPE=self)`; SQL: the send `approved`, never `applying`; the server log has `committer <mb>: SEND_SCOPE=self, 1 approved sends wait` once.     11. Expiry: seed one more case; after the approval message, SQL `update actions set notified_at = now() - interval '49 hours' where id = '<send id>';` (as `postgres` through `$D exec`) then `bun run job:run --name actions.expiry` (the server keeps running: the expiry job is conditional) → the send `expired` / `timeout`, the delegation `cancelled` / `expired`, the draft removed, phone `⌛ Not sent: the approval expired (48 h) · …`.
    12. Reminder set: on the `sent` delegation of step 6 (now `done`: use a fresh case: seed, approve, send, do not reply) SQL `update delegations set due_at = now() - interval '1 day' where id = '<id>';` then `bun run job:run --name delegation.chaser --force` → the delegation `overdue`, a reminder pair (`last_reminder_at` set at planning), audit `delegation.chaser_run`; phone `📤 Send 1 reminder?` with the item line (name, address, subject) → tap `📤 Send all` → within a minute the reminder is in the delegate's INBOX (`Re: Fwd: …`, `In-Reply-To` = the sent id, no quote, no due line when the original draft had none), `reminders_sent` 1; a second `job:run --force` the same day → no new pair (the 3-day gap and the pending-reminder rule); without `--force` → `skipped: "gate"` in the log.

    14. Logs: the terminal output has no subject, address, task text or SMTP reply text of the run (grep the markers: the case subjects and the delegate address) and no `error` line except the expected ones (none).
    15. Stop the server with Ctrl+C → ends within 15 s. Reset: `mailbox:settings switch --name create_draft --value off`, `mode --mode shadow`; `delegates:disable` the dev delegate.
