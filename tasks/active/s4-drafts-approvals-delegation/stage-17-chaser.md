## Stage 17 — `delegation.chaser`: overdue, reminder pairs, sets, the daily gate [risky]

Why risky: the chaser plans mail to people on a clock. It must run once per day, never double a reminder, and never remind an inactive delegate or an answered delegation.

- [x] **17.1 `createChaserJob` (D21, D23, P4)**
  - Goal: once per mailbox per local day at or after 07:30, every due delegation becomes `overdue` and gets at most one new reminder pair, all reminders of the run in one approval set; a closed delegation never gets one.
  - Files: create `apps/server/src/modules/delegation/chaser.ts`, `apps/server/test/integration/delegation-chaser.test.ts`; change `apps/server/src/modules/delegation/index.ts`, `apps/server/src/modules/audit/repo.ts` (`countMailboxEventsBetween(db, ctx, event, mailboxId, range)`: as `countEventsBetween` with `data->>'mailbox_id' = mailboxId`), `audit/index.ts`.
  - Interfaces:

    ```ts
    export const CHASER_LOCAL_TIME = "07:30";
    export const REMINDER_GAP_MS = 3 * 24 * 3_600_000;
    export const MAX_REMINDERS = 2;
    export const CHASER_SET_LIMIT = 10; // the set request shows every item with its task within 4096 characters (stage 14.2, review round 2 N25)
    export interface ChaserDeps {
      db;
      now(): Date;
    }
    export function createChaserJob(deps: ChaserDeps): { run(opts?: { force?: boolean }): Promise<void> };
    export function reminderDecision(
      row: {
        status: "sent" | "overdue";
        reminders_sent: number;
        last_reminder_at: Date | null;
        delegate_active: boolean;
      },
      pendingReminders: number,
      now: Date
    ): { markOverdue: boolean; remind: boolean }; // pure, exported for tests
    export async function runChaserForMailbox(
      deps: ChaserDeps,
      ctx,
      mailbox: { id: string; timezone: string; settingsVersion: string }, // settingsVersion = getMailboxSettings(…).version (M13)
      now: Date,
      opts?: { force?: boolean }
    ): Promise<{ overdue: number; reminders: number; skipped: "gate" | "settings" | null }>;
    ```

  - Decisions:
    - `run({ force })`: `listSyncTargets(db)` (active mailboxes); per mailbox: `settings = getMailboxSettings` (none, `mode !== "assist"`, or `create_draft` off → `skipped: "settings"`); `organization = getOrganization` (timezone); the gate, unless `force`: `localDateTime(now, timezone).time >= CHASER_LOCAL_TIME` and `countMailboxEventsBetween(db, ctx, "delegation.chaser_run", mailboxId, { after: localToInstant(localKey(now, tz).slice(0, 10), "00:00", tz) − 1 ms, until: now }) === 0` (the local day of `now`; `localKey` / `localToInstant` of `core/digest/local-time.ts`), else `skipped: "gate"`. `force` (the `job:run --force` flag, stage 18) skips the time and the day marker; the pending-reminder rule and the 3-day gap still hold, so a forced run can never double a reminder. One mailbox's error never stops the next.
    - **The settings guard (M13).** S3 (`4376875`, `958d749`) made `saveTriage` share-lock the settings row and compare its version before it inserts actions (`lockSettingsForShare`, `config/repo.ts:56-70`; `triage/service.ts:130-137`); a setter (`FOR UPDATE`) then waits for the writer, or the writer sees the setter's commit. The chaser needs the same guard: without it, a gate close (`create_draft off`, `mode shadow`) between the settings read in `run()` and the chaser transaction leaves a reminder pair that the setter's send close (stage 13.2) never saw. So the **first statement** of the `runChaserForMailbox` transaction is `version = await lockSettingsForShare(trx, ctx, mailbox.id)` (the `config` index); `version !== mailbox.settingsVersion` (also `undefined`) → the transaction writes nothing (no `overdue`, no pair, no day marker) and the call returns `{ overdue: 0, reminders: 0, skipped: "settings" }`; the next tick reads the settings again. `run()` passes `settingsVersion: settings.version` (`getMailboxSettings`, the same read as the settings check).
    - `runChaserForMailbox`: `rows = listDueDelegations(db, ctx, mailboxId, { now, limit: 200 })`; `setId = randomUUID()`; one transaction (after the settings guard above): for each row `locked = lockDelegation(trx, ctx, row.id)` (`FOR UPDATE`) and the status re-read: not `sent | overdue` any more (a reply was triaged a moment ago, or the user closed it) → skip (reviewer finding 7); `pending = countPendingReminderSends(trx, ctx, row.id)`; `decision = reminderDecision(locked, pending, now)`; `markOverdue` → `markDelegationOverdue` + audit `delegation.overdue`; `remind` (only while the set holds fewer than `CHASER_SET_LIMIT` reminders; the rest wait for the next day) → `n = locked.reminders_sent + 1`; the original mail (`getEmailMeta(row.email_id)`: `message_id_header`, `references_header`, `subject`); the original draft (`getDraft(row.draft_action_id)`: its payload gives `language` and `due_date`); `thread = { in_reply_to: row.sent_message_id, references: [...originalReferences, originalMessageId, row.sent_message_id].filter(Boolean, unique) }`; `draft = { kind: "reminder", delegate_id, delegate_name, to: [delegate_email], task: row.task_summary, due_date: <the original draft's due_date, "" when it had none: the delegate never reads a date nobody set>, language: <the original draft's language, "en" when missing>, delegation_id: row.id, reminder: n, thread }`; `day = localKey(now, tz).slice(0, 10)`; `createPlanned(trx, ctx, row.email_id, [{ type: "create_draft", payload: draft, status: "ready", idempotencyKey: `${emailId}:create_draft:reminder:${day}`}, { type: "send", payload: { ...sendPayloadFor(draft), set_id: setId }, status: "awaiting_approval", idempotencyKey:`${emailId}:send:reminder:${day}`, dependsOn: "create_draft" }])` (one reminder per delegation per local day; a crash after the rows makes the next run's insert a no-op: an empty result counts as not created); then `markReminderPlanned(trx, ctx, row.id, now)` (**`last_reminder_at` moves at planning**, so a rejected or expired reminder still keeps the 3-day gap; `reminders_sent` moves when the reminder send is `applied`, D11). Then audit `delegation.chaser_run` (`data: { mailbox_id, due: rows.length, overdue, reminders, set_id, forced }`) in the same transaction — the marker of the local day (written on every gated run, also with 0 due rows; a forced run writes it too, with `forced: true`).
    - `reminderDecision`: `markOverdue` = `status === "sent"`; `remind` = `delegate_active && pendingReminders === 0 && reminders_sent < MAX_REMINDERS && (last_reminder_at === null || now − last_reminder_at >= REMINDER_GAP_MS)`.
    - The `delegation` module imports `actions` (`createPlanned`, `getDraft`), `mail` (`getEmailMeta`, stage 7), `config` (`getMailboxSettings`, `lockSettingsForShare`: M13), `tenancy`, `audit` (D29). It runs no mailbox or SMTP call.
    - Log: `chaser <mailboxId>: due <n>, overdue <o>, reminders <r>` when `n > 0`; `chaser <mailboxId>: skipped settings` once per process per mailbox (`warnedSettings` set); `chaser <mailboxId>: forced` when `force`.
