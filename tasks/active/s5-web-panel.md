### Round 1 — product and stack (sent 2026-11-08; answers pending)

Each question has a proposed default and the reason. The answers become P1–P12 under "User decisions".

1. **Login method.** Default: password login. The hash is argon2id through `Bun.password` (built into Bun, no library). The first password and every reset come from a one-time setup link that the CLI prints (`bun run web:invite --org-id … --user-id …`, 24 h, one use; its SHA-256 hash is stored, like the Telegram link token). Sessions: a `web_sessions` table (32 random bytes, SHA-256 stored, 30 days sliding, 90 days absolute), cookie `HttpOnly; Secure; SameSite=Lax; Path=/`. Login attempts: 5 failures lock the user for 15 minutes; one counter per user in the DB. Why: no outside service; it works before a mailbox or Telegram exists (the S5 owner still comes from `org:create`); recovery through the CLI in the pilot. Rejected: e-mail magic link (needs a system mail sender; it comes with the S6 sign-up and can replace the password then), a Telegram code (not possible before the link exists), passkeys (a WebAuthn library and device recovery; possible later as a second factor).
2. **Web stack.** Default: keep Astro 5 and switch to `output: "static"`; remove `@astrojs/node` and `@astrojs/sitemap`; React 19 islands (shadcn, Tailwind 4), one island per page, data from the JSON API with `fetch`; the Hono server serves `apps/web/dist` from the same origin (`serveStatic` from `hono/bun`) and redirects every page except `/login` and `/setup` to `/login` when the session cookie is missing; the API lives under `/api/*`. Why: the roadmap prefers "a static build served by the server"; one process, one container, one origin (no CORS, the cookie just works); the starter stays. Rejected: Astro SSR with the node adapter (a second runtime and sessions in two places), a separate Vite SPA (drops the starter for no gain).

**HTTP platform**

- **D5 Hardening on every request** (S5a). Order of middlewares in `createApp`: access log (debug level: method, **route pattern**, status, ms; never the raw path or the query string), `secureHeaders()` with the header CSP `default-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; frame-ancestors 'none'; form-action 'self'; base-uri 'self'` and **no `script-src` or `style-src` in the header**: Astro inlines the island runtime and a style on every `client:load` page (probe 2026-11-08: 2 inline `<script>`, 1 inline `<style>`, also with `inlineStylesheets: "never"`), so the page's own `<meta http-equiv="content-security-policy">` from Astro `experimental.csp` (D17) carries `script-src 'self' 'sha256-…'` and `style-src` with the hashes; the header carries what a meta tag cannot (`frame-ancestors`) and the rest; the two policies intersect. Never `'unsafe-inline'`. S5a stage 13 test: Playwright asserts no CSP console error and no `securitypolicyviolation` event on an app page (cold review finding 1; the stage number and the event check: second cold review of the S5a plan, 2026-11-08), `X-Frame-Options: DENY`, HSTS only when `WEB_BASE_URL` starts with `https://`; `bodyLimit` 64 KB; the origin check for every non-safe method under `/api/*`: `Sec-Fetch-Site` must be `same-origin` **or** `Origin` must equal the origin of `WEB_BASE_URL` or one of `WEB_TRUSTED_ORIGINS`, else 403 `{ error: "bad_origin" }` (Hono's `csrf()` covers only form content types, see the facts); `/api/auth/*` keeps Better Auth's own `trustedOrigins` check. `/health` stays public and unchanged. **API conventions**

- **D9 JSON API.** Base `/api`; requests and responses are JSON; ids are UUIDs (`z.uuid()`); times are ISO 8601 UTC strings; the client converts to the organization timezone (U8). ### Rules for every step (read before each step; the segment plans copy this block)

- Code rules: `docs/code-patterns.md`. `packages/core` has no I/O. Other modules import a module only through its `index.ts`. Every repository function takes a `TenantContext` and filters by `org_id`; the only new exception is `listMembershipsOfUser` (D3). Template literals, no `+` for strings. `createLog("<module>")`, never `console.log`. A status change and its `audit_log` row go in one transaction.
- **Dependencies:** `better-auth` stays pinned to an exact version; Dependabot (`.github/dependabot.yml` at the workspace root, `package-ecosystem: bun`, weekly, only `better-auth`) opens the upgrade PRs; an upgrade runs the auth integration tests and the Playwright login smoke before the merge (D1). `bun.lock` changes only in the stage that adds the package.
- **Routes are thin** (D8): parse with the core schema, call one service, map to JSON. No SQL, no business rule, no `org_id` from the request. Every route test covers: no session → 401, an assistant on an owner route → 403, another organization's id → 404, a bad body → 400 with `details`.
- **No secret or private text in a log line, an error body or an audit row.** Never the mailbox password, the Better Auth token or cookie, `WEB_AUTH_SECRET`, an e-mail address, a subject, a pattern, a reason text. Access log = route pattern + status + ms at `debug`. Errors through `describeError`.
- **Web strings** live in `apps/web/src/i18n/en.ts` (U1); a component never holds a user-visible literal. No inline `<script>` and no hand-written `<style>` (D5 CSP: the build hashes the scripts; styles come from Tailwind classes; `'unsafe-inline'` on `style-src` exists only for the Radix scroll lock). shadcn components come from the shadcn CLI. `react-compiler` and `jsx-a11y` lint errors are fixed, never disabled.
- **Tests:** unit next to the code; integration in `apps/server/test/integration/` with `withRollback` and the fixtures; route tests with `app.request()` and an injected `getSession`; Playwright in `apps/web/e2e/` on the seed of D19, both projects. Fixed `Date` values; the organization timezone `Europe/Warsaw` in tests.
- **Checks** after each step (the step names which): `bun run lint && bun run typecheck && bun run test:unit`; with DB: `bun run dev:up && bun run db:migrate && bun run test:int`; web: `bun run web:build`; e2e: `bun run test:e2e`. Markdown: `bunx prettier --check <files>`.
- **Scopes and env:** no step changes `.env`; `ACTIONS_SCOPE`, `SEND_SCOPE`, `TRIAGE_LLM_SCOPE` keep their values; only the e2e config sets `ACTIONS_SCOPE=synthetic` for the test server. **Do not touch the VPS** before S5e and the user's go. Never print or edit any `.env`.
- Do not commit (the main session commits each stage after the review). Never run `bun run format` or `prettier --write` outside the step's files (S2 incident). Format only your files.
- Worktrees: the dev DB, GreenMail and the ports in `.env` are shared; `bun run db:worktree <name>` gives an own database when two tasks run at once; only one checkout runs `test:int`, `db:migrate` or a dev server at a time; only one task at a time adds a migration or changes `bun.lock` (`tasks/README.md`).
