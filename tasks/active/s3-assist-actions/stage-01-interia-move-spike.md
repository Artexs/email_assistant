## Stage 1 — Interia move spike: `mailbox:probe-move` on the real mailbox [risky]

Why first: the "Not verified" Interia items (delimiter, `COPYUID`, size and date after a COPY, `SEARCH SINCE` in a folder, `UID EXPUNGE`, the UID after a move back, flags) decide the rules of stages 4, 5 and 9. The probe changes the real pilot mailbox, but only with one synthetic mail in a new probe folder, and it cleans up after itself. It runs on the Mac against Interia directly (no VPS, no DB): the user types the Interia password on stdin.

- [ ] **1.1 CLI `mailbox:probe-move` (test address only)**
  - Goal: one command that performs every IMAP write that S3 will use, on one synthetic mail, and prints facts only.
  - Files: create `apps/server/src/modules/mail/imap/probe-move.ts`, `apps/server/src/scripts/mailbox-probe-move.ts`, `apps/server/test/integration/imap-probe-move.test.ts`; change `package.json` (script `"mailbox:probe-move": "bun apps/server/src/scripts/mailbox-probe-move.ts"`), `apps/server/src/modules/mail/index.ts` (export `probeMove`, `type ProbeMoveReport`).
  - Interfaces:
    - `probeMove(imap: ImapConnectOptions, opts: { probeId: string; now: Date; log?: (line: string) => void }): Promise<ProbeMoveReport>`.
    - `interface ProbeMoveReport { delimiter: string | null; namespace: { prefix: string; delimiter: string | null }; capabilities: { move: boolean; uidplus: boolean }; probeFolder: string; append: { uid: number | null }; copy: { uidMapReturned: boolean; targetUid: number | null; sameUidAsSource: boolean | null }; targetMeta: { found: boolean; sameSize: boolean | null; sameInternalDate: boolean | null; sameEnvelopeDate: boolean | null; sameMessageId: boolean | null }; searchSinceInFolder: { found: boolean }; expunge: { otherDeletedKept: boolean; inboxOtherDeleted: number; inboxExpungeSkipped: boolean; sourceGone: boolean | null }; moveBack: { uidMapReturned: boolean; inboxUid: number | null; sameAsOriginal: boolean | null; aboveUidNext: boolean | null }; flags: { flaggedKept: boolean; seenKept: boolean; flaggedRemoved: boolean; seenRemoved: boolean }; cleanup: { probeMailDeleted: boolean; folderDeleted: boolean }; notes: string[] }`.
    - The script: `bun run mailbox:probe-move --host <imap host> --port <port> --address <address>`; the password on stdin (`printf '%s' "$P" | bun run mailbox:probe-move …`); it refuses unless `TEST_MAILBOX_ADDRESS` equals `--address` (case-insensitive; the same guard as `seedMailbox`). The guard is `assertTestAddress(address, testAddress)` in `mail/imap/probe-move.ts` (exported from there, not from the script: importing a script runs its main code). Exit 0 with the report as `key: value` lines; exit 1 on an error, with the cleanup notes (`withCleanupNotes` from `probe.ts`).
  - Decisions:
    - The probe folder is `AI/Probe-<first 8 hex of probeId>` created with `mailboxCreate(["AI", "Probe-…"])` (imapflow joins the parts with the delimiter): this tests D9 (the real path of an `AI/*` folder). `delimiter` comes from `list()` (the INBOX entry). `namespace` is `client.namespace` after the connect (the personal prefix and its delimiter): imapflow's `normalizePath` adds the prefix to every path and joins array paths with the namespace delimiter, so stage 4's `matchFolder` must compare the paths after the prefix.
    - The probe mail is a `renderSeedMessage` with `Message-ID <probe-<probeId>@ea-seed.test>`, subject `EA probe move <probeId>`, `X-EA-Probe: <probeId>`, text "Email assistant move probe. You can delete it." APPEND into INBOX; `uid` from `AppendResponseObject` (UIDPLUS), else found with `SEARCH SUBJECT`.
    - Steps in order, each guarded, each result into the report: (1) `UID FETCH` in INBOX (`uid, size, internalDate, envelope, flags`); (2) `messageFlagsAdd(uid, ["\\Flagged", "\\Seen"], { uid: true })`, FETCH flags again → `flaggedKept`, `seenKept`; (3) `messageCopy(uid, probeFolder, { uid: true })` → `uidMapReturned`, `targetUid`; (4) in the probe folder: `status`/`search({ all: true })` → the UIDs; FETCH the one (or the `targetUid`) → compare size, INTERNALDATE (same millisecond), ENVELOPE date and `Message-ID` with step 1; (5) `search({ since: <now − 2 days> })` in the probe folder → `found`; (6a) the `UID EXPUNGE` test, only in the probe folder, never in INBOX: APPEND two more probe mails A and B (the same shape, subjects `EA probe move <probeId> A` / `B`) into the probe folder, set `\\Deleted` on both, `messageDelete(A, { uid: true })` (UID EXPUNGE with UIDPLUS; the probe refuses this step without UIDPLUS), then `UID FETCH B` → `otherDeletedKept` (B is still there: the server expunged only the given UID) and `UID FETCH A` must be empty (else the note `UID EXPUNGE removed nothing`); clear `\\Deleted` on B so the cleanup deletes it by its own UID; (6b) in INBOX, under the INBOX expunge rule below: allowed → `messageDelete(uid, { uid: true })` (it sets `\\Deleted` itself), `UID FETCH uid` → `sourceGone`; not allowed → no expunge (`inboxExpungeSkipped` true, `inboxOtherDeleted` = the count of the other `\\Deleted` UIDs, `sourceGone` null), and go on with step 7. No step counts INBOX mail (new mail during the probe would change a count); (7) `messageCopy(targetUid, "INBOX", { uid: true })` from the probe folder → `uidMapReturned`, `inboxUid` (from the map, else `SEARCH SUBJECT` in INBOX); compare with the original uid → `sameAsOriginal` (when step 6b skipped the expunge, the original still holds its UID: `sameAsOriginal` = null and the note `not measured: the original probe mail was not expunged`); compare with `STATUS (UIDNEXT)` read before step 7 → `aboveUidNext`; (8) in INBOX: `messageFlagsRemove(inboxUid, ["\\Flagged", "\\Seen"])`, FETCH → `flaggedRemoved`, `seenRemoved`; (9) cleanup: delete the INBOX probe mails (the copy of step 7 and, when step 6b skipped, the original) with `messageDelete` (UID EXPUNGE), each under the INBOX expunge rule below; a delete that the rule does not allow is skipped, and the notes name the subject and the UID that stays ("delete it by hand") → `probeMailDeleted` (true only when no INBOX probe mail stays); delete the probe-folder copies (the copy and B) the same way (the probe folder holds only probe mail, so the rule does not apply there), then `mailboxDelete(probeFolder)` → `folderDeleted`.
    - INBOX expunge rule (re-review RM2; it covers every expunge in INBOX, in step 6b and in step 9): run `messageDelete` in INBOX only when `expunge.otherDeletedKept` is true (step 6a proved that the server expunges only the given UID) and a `search({ deleted: true })` in INBOX right before it returns no UID other than the probe mail's own. Else skip it. Why: on a server that ignores the UID set, a `UID EXPUNGE` in INBOX would also expunge the user's own `\\Deleted` mail.
    - A failure after the APPEND throws with the cleanup notes: the probe mail subject and the probe folder name, "delete them by hand". The probe never touches any other mail: every write names one UID; the only EXPUNGE is `UID EXPUNGE <uid>`.
    - Log lines (the script `log`): counts, booleans, UIDs and the folder name only (the folder name is the probe's own, not mail data).
  - Test (`imap-probe-move.test.ts`, GreenMail, a fresh `u-<uuid>@localhost` user as in `imap-contract.test.ts`): `probeMove` returns `delimiter` `"."` or `"/"` (not null), `append.uid` > 0, `copy.uidMapReturned` true, `targetMeta.found` true with all four `same…` true, `searchSinceInFolder.found` true, `expunge.otherDeletedKept` true, `expunge.inboxOtherDeleted` 0, `expunge.sourceGone` true, `namespace.prefix` a string, `moveBack.inboxUid` > 0, all four flag booleans true, both cleanup booleans true; after the run the GreenMail user has no probe folder and no mail with the probe subject. Second test: the address guard `assertTestAddress` from `mail/imap/probe-move.ts` (a unit case: another address throws, the same address in other case passes). Third test: a GreenMail INBOX mail of the test user with `\\Deleted` set before the probe → `inboxExpungeSkipped` true, `inboxOtherDeleted` 1, `moveBack.sameAsOriginal` null, `cleanup.probeMailDeleted` false, the notes name the INBOX probe mails, and that mail is still there after the run; the test then deletes its own `\\Deleted` mail and the probe mails (GreenMail obeys `UID EXPUNGE`, so this test checks the skip logic, not the server).
  - Check: `bun run dev:up && bun run lint && bun run typecheck && bun run test:unit && bun run test:int`.
  - Done when: the GreenMail test passes and `bun run mailbox:probe-move` prints the usage without arguments.
  - Out of scope: the port methods (stage 3: the probe uses `imapflow` directly, like `probe.ts`); any write to a mail that is not the probe mail.

- [ ] **1.2 Run the probe on the pilot Interia mailbox (user step) and record the facts**
  - Goal: the "Not verified" Interia items become facts in the note; the stage 4, 5 and 9 decisions are settled (user checkpoint 1).
  - Files: change `notes/2026-11-03-interia-imap-capabilities.md` (append a section "Move probe (S3 stage 1, <date>)" with the report lines), this task file ("Results": the report; a log line).
  - Interfaces: none (operations).
  - Decisions:
    - The command on the Mac: `read -rsp 'Interia password: ' P && printf '%s' "$P" | TEST_MAILBOX_ADDRESS=<pilot address> bun run mailbox:probe-move --host poczta.interia.pl --port 993 --address <pilot address>; unset P`. The agent never sees or prints the password; the user runs the `read` line. The report holds no mail data.
    - The probe runs while the VPS server keeps syncing: the probe mail is a synthetic mail above the cursor, so the VPS stores it as a normal seed mail (and triages it when `TRIAGE_LLM_SCOPE` is `synthetic` or `all`: one LLM call). After step 9 it is gone from INBOX; the VPS row stays (folder INBOX, like a user delete). Accepted: one stray synthetic row.
    - INBOX mail that is marked deleted but not expunged (rare in webmail) makes the probe skip every INBOX expunge (step 6b and the INBOX part of step 9). The report then says `inboxExpungeSkipped: true` and `moveBack.sameAsOriginal: null`, and the INBOX probe mails stay (the notes name them). Then the user deletes the probe mails and empties the deleted mail in webmail, and runs the probe again before checkpoint 1, because the stage 6 rule below needs `sameAsOriginal`.
    - Outcomes to write down, each as one line: `delimiter`, `namespace.prefix`, `namespace.delimiter`, `copy.uidMapReturned`, `copy.sameUidAsSource`, `targetMeta.sameSize`, `targetMeta.sameInternalDate`, `targetMeta.sameEnvelopeDate`, `searchSinceInFolder.found`, `expunge.otherDeletedKept`, `expunge.inboxOtherDeleted`, `expunge.sourceGone`, `moveBack.sameAsOriginal`, `moveBack.aboveUidNext`, the four flag booleans, the cleanup booleans.
    - How the facts change later stages (the main session edits the stage files at checkpoint 1): `sameSize` false and `sameInternalDate` true → stage 5 identity mode `no_size` (`Message-ID` + From + INTERNALDATE); `sameSize` false and `sameInternalDate` false → stop: no identity is left, the build waits for a new design; `moveBack.sameAsOriginal` true → stage 6 depends on its folder check on each hit (a copy back to INBOX lands at the old UID below the cursor; the folder check is built in every case, this fact says it is needed); a non-empty `namespace.prefix` → stage 4 `matchFolder` compares after the prefix; `uidMapReturned` false or `sameUidAsSource` true → stage 9 keeps the source UID as the hint and relies on `locateMessage` (already the plan: no change); `searchSinceInFolder.found` false → stage 5 falls back to `search({ all: true })` with a UID range cap (`<highest − 2000>:*`) [design the fallback at the checkpoint]; `otherDeletedKept` false → stop: `UID EXPUNGE` is not safe at Interia (it would expunge the user's own `\Deleted` mail) and moves must stay `log only` (policy `movesSupported` false for this mailbox) until a new design; `delimiter` not `/` → stage 9 D9 writes the real path into `folder_map`.
  - Test: none (operations).
  - Check: the report prints with exit 0; the pilot INBOX in webmail has no `EA probe move` mail and no `AI/Probe-…` folder (the user looks).
  - Done when: the note has the facts and the user said go at checkpoint 1.
  - Out of scope: any probe on real mail; the VPS.
